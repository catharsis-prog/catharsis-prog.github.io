# 2. extends

## Где вы это уже видели

В прошлом уроке мы разобрались, когда наследование уместно: когда можно честно сказать «это является тем». Теперь пора посмотреть, как эта идея выглядит в коде.

Ключевое слово `extends` — это то, чем в Java выражается наследование. Читается буквально: «расширяет». Класс-наследник расширяет класс-родитель — добавляет к нему что-то своё, сохраняя всё, что было у родителя.

**Ситуация первая.** Вы смотрите на квартиру и говорите: «Это двушка». У двушки есть всё, что есть у любой квартиры: стены, пол, потолок, входная дверь, кухня, санузел. Плюс есть что-то своё: две комнаты. Двушка **расширяет** понятие «квартира» — она квартира плюс одна дополнительная характеристика. Это и есть `extends`: наследник содержит всё, что было у родителя, и добавляет что-то своё.

**Ситуация вторая.** Вы смотрите на договор. Есть базовый договор: номер, дата, стороны, подписи. Есть договор аренды: всё то же самое плюс адрес объекта, срок аренды, размер платежа. Договор аренды **расширяет** базовый: он содержит все поля базового и добавляет свои.

**Ситуация третья.** Вы работаете в компании и смотрите на должности. У любого сотрудника есть имя, табельный номер, оклад, дата приёма. У менеджера есть всё то же самое плюс список подчинённых и право проводить совещания. Менеджер **расширяет** сотрудника. Если вы уволите менеджера, — это всё равно увольнение сотрудника.

**Ситуация четвёртая.** Вы смотрите на модели машин. У всех машин есть колёса, двигатель, руль, тормоза. У электромобиля есть всё то же самое плюс батарея вместо бензобака и режим рекуперации. Электромобиль **расширяет** машину: он машина плюс несколько дополнительных особенностей.

**Ситуация пятая.** Вы работаете с заказами. У любого заказа есть номер, дата, список позиций, сумма. У срочного заказа есть всё то же самое плюс доплата за срочность и срок доставки «завтра». Срочный заказ **расширяет** обычный.

**Ситуация шестая.** Вы видите в коде:

```java
class Dog extends Animal {
    void bark() { ... }
}
```

— и понимаете, что у `Dog` есть всё, что есть у `Animal`, плюс `bark()`. Но что именно «всё»? Все поля? Все методы? Что происходит с конструкторами? А если у `Animal` есть приватное поле — увидит ли его `Dog`? И почему при создании `Dog` вызывается конструктор `Animal`? Эти вопросы мы и разберём в этом уроке.

Если последняя ситуация вам знакома — урок для вас. Если остальные тоже — отлично, интуиция про «расширение» у вас уже есть.

## Синтаксис

В Java наследование выражается одним словом:

```java
class Dog extends Animal {
    // ...
}
```

Здесь `Dog` — подкласс (наследник, потомок), `Animal` — суперкласс (родитель, предок). В литературе можно встретить все эти термины; они означают примерно одно и то же. Мы будем использовать «подкласс» и «суперкласс».

Одно важное ограничение: **в Java у класса может быть только один суперкласс**. Множественное наследование (когда `class Dog extends Animal, Pet`) в Java запрещено. Об этом мы поговорим ближе к концу урока, но запомните сразу: `extends` — только один класс.

Если класс не расширяет ничего явно, — он всё равно расширяет `Object`. Это корень иерархии всех классов в Java. В следующем разделе разберёмся, что это значит.

## Что наследуется

Когда `Dog` расширяет `Animal`, `Dog` получает:

**Все поля.** Даже `private`. Но к `private`-полям `Animal` `Dog` не имеет доступа напрямую — об этом ниже.

**Все методы.** Кроме `private` (их не видно) и кроме конструкторов (они не наследуются вообще — об этом тоже ниже).

**Все вложенные классы, интерфейсы, перечисления.** Если они были в `Animal`, они видны и в `Dog`.

Вот пример:

```java
class Animal {
    String name;
    int age;

    void eat() {
        System.out.println(name + " ест");
    }

    void sleep() {
        System.out.println(name + " спит");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println(name + " гавкает");   // name доступно — оно package-private
    }
}
```

Теперь `Dog` умеет `eat()`, `sleep()`, `bark()`, и у него есть поля `name` и `age`. Если создать `Dog` и вызвать `eat()`, — метод возьмётся из `Animal`, но работать будет с полями **этого конкретного** `Dog`.

```java
Dog dog = new Dog();
dog.name = "Рекс";
dog.age = 3;

dog.eat();     // Рекс ест  (метод из Animal)
dog.bark();    // Рекс гавкает  (метод из Dog)
```

Обратите внимание: `dog.eat()` — это метод `Animal`, но он использует `name` и `age`, которые принадлежат конкретному `dog`. То есть **наследуются не значения полей, а их описания**. У каждого объекта `Dog` — свои значения `name` и `age`, но набор полей одинаковый.

## Что не наследуется

**Конструкторы.** Это самое частое недоразумение. Конструктор — это не метод в обычном смысле, и он **не наследуется**. Если у `Animal` есть конструктор `Animal(String name)`, — у `Dog` его **нет**. `Dog` должен либо определить свой конструктор, либо использовать конструктор по умолчанию.

Об этом мы поговорим подробнее в следующем разделе, но запомните: **конструкторы не наследуются**.

**`private`-члены.** Точнее, они наследуются, но **недоступны** в подклассе. Поле `private int secret` в `Animal` — есть и у `Dog`, но `Dog` не может к нему обратиться напрямую. Только через методы `Animal`, которые к нему обращаются.

```java
class Animal {
    private int secret = 42;

    int getSecret() { return secret; }   // public-метод — можно вызвать из Dog
}

class Dog extends Animal {
    void peek() {
        // System.out.println(secret);   // НЕ скомпилируется: private
        System.out.println(getSecret()); // а так — можно
    }
}
```

**`static`-члены.** Формально они наследуются, но доступ к ним идёт через класс, а не через объект. `Dog.someStatic` будет работать, если `someStatic` объявлено в `Animal`. Но это не «наследование» в полном смысле: `static`-поле существует одно на `Animal`, и через `Dog` вы обращаетесь к тому же полю.

**`final`-методы.** Их можно унаследовать, но нельзя переопределить. Об этом — в уроке 5.

## Конструкторы и невидимый super()

Это самая тонкая часть, и ей стоит уделить внимание.

Когда вы создаёте объект подкласса, — **сначала вызывается конструктор суперкласса, потом конструктор подкласса**. Даже если вы этого не пишете. Java автоматически вставляет вызов `super()` — конструктора родителя без параметров — в начало каждого конструктора.

```java
class Animal {
    Animal() {
        System.out.println("Animal()");
    }
}

class Dog extends Animal {
    Dog() {
        // сюда Java невидимо вставит super()
        System.out.println("Dog()");
    }
}

new Dog();
// Animal()
// Dog()
```

Обратите внимание на порядок: сначала `Animal()`, потом `Dog()`. Это логично: чтобы объект `Dog` был полноценным, сначала нужно «построить» его часть `Animal`, а потом добавить «часть `Dog`».

Это **порядок инициализации**, о котором мы говорили в уроке 4 (модуль 1). Только теперь он идёт не в одном классе, а в цепочке классов: сначала все родители, потом сам класс.

**Что если у `Animal` нет конструктора без параметров?** Тогда `super()` не сработает, и Java потребует **явно** вызвать `super(...)` с параметрами:

```java
class Animal {
    Animal(String name) {
        // ...
    }
}

class Dog extends Animal {
    Dog(String name) {
        super(name);   // обязательно, иначе не скомпилируется
        // ...
    }
}
```

`super(...)` должен быть **первой строкой** в конструкторе — так же, как `this(...)`. И так же, как с `this(...)`, — нельзя вызвать и `this(...)`, и `super(...)` одновременно (потому что оба должны быть первыми).

Если `Animal` не определяет никаких конструкторов — Java подставляет `Animal()` по умолчанию, и `super()` работает невидимо. Как только вы определяете хоть один конструктор в `Animal` — конструктор по умолчанию исчезает, и `Dog` должен явно вызвать `super(...)` с параметрами.

Это та же самая механика, что мы разбирали в уроке 4 модуля 1, только теперь она применяется к цепочке классов.

## Все классы наследуются от Object

В Java **каждый класс** (независимо от того, написали вы `extends` или нет) наследуется от `java.lang.Object`. Это корень всей иерархии.

Если вы написали `class Dog extends Animal` — `Dog` наследует `Animal`, а `Animal` наследует `Object`. То есть `Dog` наследует всё, что есть в `Object`, через `Animal`.

Если вы написали просто `class Dog` — `Dog` наследует `Object` напрямую. Даже если не писали `extends` явно.

`Object` даёт несколько методов, которые есть у **любого** объекта в Java:

- `equals(Object)` — сравнение на равенство;
- `hashCode()` — хеш-код;
- `toString()` — строковое представление;
- `getClass()` — класс объекта;
- `clone()` — копирование (если реализован `Cloneable`);
- `finalize()` — устаревший метод, о котором мы говорили в уроке 7 модуля 1.

Все эти методы можно **переопределять** в своих классах. Мы уже делали это с `toString()` в практикуме. Об этом мы будем говорить подробнее в уроке 4, но запомните: **`Object` — общий предок всех классов**, и это объясняет, почему переменная типа `Object` может хранить любой объект.

```java
Object o = new Dog("Рекс");   // можно: Dog — это Object
Object o2 = "Привет";          // можно: String — это Object
Object o3 = 42;                // можно: Integer — это Object
```

Это свойство очень полезно: например, коллекции до появления обобщений (`generics`) хранили `Object`, и в них можно было положить что угодно. Сейчас так почти не делают, но понимать, откуда это растёт, полезно.

## Аналогия, которая помогает

Хорошая аналогия — **конструктор LEGO и готовые наборы**.

Представьте базовый набор LEGO: несколько кубиков, пластина, инструкция. Из него можно собрать что угодно — но это «что угодно» состоит из базовых деталей.

Теперь представьте **набор «Машина»**. В нём есть всё то же, что в базовом наборе (кубики, пластина), плюс колёса, руль, лобовое стекло и инструкция по сборке машины. Набор «Машина» **расширяет** базовый набор: он содержит все базовые детали и добавляет свои.

Когда вы собираете машину, — вы используете **все** детали: и базовые (кубики, пластина), и дополнительные (колёса, руль). Если вы потеряете инструкцию от «Машины», — по инструкции от базового набора вы сможете собрать что-то простое, но не машину. И наоборот: инструкция от «Машины» не поможет собрать базовый набор.

**`extends`** — это как «набор „Машина“ расширяет базовый набор». Все базовые детали на месте, плюс свои.

**Конструкторы** — это инструкции. У «Машины» своя инструкция, у базового набора — своя. Одна не наследует другую; но чтобы собрать «Машину», нужно сначала собрать базовый набор, а потом добавить к нему детали. Это и есть `super()`: сначала выполняется «инструкция родителя», потом «инструкция наследника».

**`private`-поля** — это как запечатанные пакетики с деталями. Вы знаете, что они есть, но открыть их нельзя. Только производитель (методы родителя) может это сделать.

И ещё одна параллель: **`Object` — это как «универсальный набор LEGO»**, из которого сделаны все остальные наборы. Даже если вы купили «Машину», в её основе всё равно лежат базовые кубики LEGO.

## Микрозадача 1

Вот код. Что выведется в каждом `println`? Объясните результат.

```java
class Animal {
    String name = "Животное";

    void speak() {
        System.out.println("Я " + name);
    }
}

class Dog extends Animal {
    String name = "Собака";

    void speak() {
        System.out.println("Гав! Я " + name);
    }
}

Animal a = new Dog();
a.speak();
System.out.println(a.name);
```

### Разбор

Выведется:

```
Гав! Я Собака
Животное
```

Разберём по шагам.

`Animal a = new Dog();` — создан объект `Dog`, но переменная типа `Animal`. Это работает, потому что `Dog` **является** `Animal` (мы это обсуждали в прошлом уроке).

`a.speak()` — здесь важно: **метод выбирается по фактическому типу объекта**, а не по типу переменной. Объект — `Dog`, поэтому вызывается `Dog.speak()`. Внутри `Dog.speak()` используется `name` — и здесь интересный момент: **поле `name` тоже выбирается по фактическому типу**. В `Dog` есть своё поле `name = "Собака"`, оно «перекрывает» `Animal.name`. Поэтому выводится «Гав! Я Собака».

`a.name` — а вот здесь **поле выбирается по типу переменной**, а не по типу объекта. Переменная `a` типа `Animal`, значит, `a.name` — это `Animal.name = "Животное"`. Поэтому выводится «Животное».

Это важное различие: **методы — по фактическому типу, поля — по типу переменной**. Методы — это поведение, и оно наследуется «правильно» (полиморфизм). Поля — это данные, и они «прячутся» (field hiding), что может привести к путанице.

Именно поэтому **не рекомендуется переопределять поля** в подклассах. Если у `Animal` есть поле `name`, а у `Dog` — тоже `name`, — вы получаете два разных поля, и какое из них видно — зависит от того, как вы обращаетесь. Это источник багов.

Правильно было бы **не переопределять `name`**, а использовать унаследованное:

```java
class Animal {
    String name;
}

class Dog extends Animal {
    Dog(String name) {
        this.name = name;   // используется поле из Animal
    }
}
```

Тогда `name` одно, и путаницы нет.

**Мораль.** Не переопределяйте поля. Переопределяйте методы. Поля — это данные объекта; если хотите изменить данные, — делайте это через конструктор или сеттер, а не через «тень» в подклассе.

## Микрозадача 2

Вот код. Он не компилируется. Найдите ошибку и объясните, почему.

```java
class Animal {
    private String name;

    Animal(String name) {
        this.name = name;
    }
}

class Dog extends Animal {
    Dog() {
        System.out.println("Собака создана");
    }
}
```

### Разбор

Ошибка в конструкторе `Dog()`. Java пытается невидимо вставить `super()` — вызов конструктора `Animal` без параметров. Но у `Animal` есть только конструктор с параметром `String name`. Конструктора без параметров нет (он был бы по умолчанию, но раз есть явный — его нет). Значит, `super()` не сработает, и компилятор скажет что-то вроде «нет подходящего конструктора в `Animal`».

**Как исправить.** Есть два варианта.

**Первый — явно вызвать `super(...)` с параметром:**

```java
class Dog extends Animal {
    Dog(String name) {
        super(name);   // передаём имя в Animal
    }
}
```

Теперь `Dog` принимает имя и передаёт его родителю. Это правильно: `Animal` требует имя, `Dog` его получает и передаёт.

**Второй — добавить в `Animal` конструктор без параметров:**

```java
class Animal {
    private String name;

    Animal() {
        this.name = "Безымянное";
    }

    Animal(String name) {
        this.name = name;
    }
}
```

Тогда `super()` сработает, и `Dog()` будет работать без изменений.

**Какой вариант лучше?** Зависит от того, что вы хотите. Если у каждого `Animal` должно быть имя, — первый вариант (заставляем передавать). Если имя опционально — второй. В большинстве случаев первый правильнее: **не давайте создавать объект без обязательных данных**.

**Мораль.** Конструкторы не наследуются. И если у родителя нет конструктора без параметров, — наследник **обязан** вызвать `super(...)` явно. Это не всегда очевидно, потому что в простых случаях Java делает это невидимо. Но как только в иерархии появляются конструкторы с параметрами, — нужно быть внимательным.

## Самостоятельная задача

Спроектируйте иерархию для системы «сотрудники компании».

В ней должны быть:

- `Employee` — базовый класс с полями `name`, `id`, `baseSalary`;
- `Manager` — наследник с полем `bonus` и списком подчинённых;
- `Intern` — наследник с полем `mentor` (наставник) и `monthsRemaining` (сколько месяцев стажировки осталось).

- какие методы можно вынести в `Employee`, а какие — специфичны для `Manager` или `Intern`;
- как считать зарплату: у `Employee` — это `baseSalary`, у `Manager` — `baseSalary + bonus`, у `Intern` — фиксированная стипендия. Где это реализовать?

Затем ответьте на вопрос: если завтра появится `SeniorManager` — наследник `Manager` с дополнительным полем `department`, — что изменится в иерархии? Какие конструкторы понадобятся, и какие вызовы `super(...)` будут?

## Что дальше

Мы разобрались с синтаксисом `extends` и с тем, что именно наследуется, а что — нет. В следующем уроке — **«`super`»** — мы поговорим о ключевом слове, которое позволяет наследнику обращаться к родителю: вызывать его методы, использовать его поля, вызывать его конструкторы. Это не такой простой инструмент, как кажется, и у него есть свои тонкости.

А пока — маленькое упражнение на наблюдательность. Посмотрите на любую иерархию классов в своём проекте (или в открытом проекте на Java). Задайте вопрос: **какой конструктор вызывается у родителя при создании наследника?** Если в родителе несколько конструкторов, — какой именно и почему? Если наследник не вызывает `super(...)` явно, — какой конструктор родителя Java вызовет невидимо, и есть ли он вообще? Просто найдите. Не чините. Понимание того, как именно устроена инициализация, — уже большой шаг к тому, чтобы не ловить странные баги.
