# 2. Класс как чертёж, объект как вещь

## Где вы это уже видели

В прошлом уроке мы говорили о том, зачем нужно ООП. Теперь пора спуститься с небес на землю и посмотреть, как эта идея выглядит в коде. И начнём мы с различения, которое кажется очевидным ровно до того момента, пока не попробуешь его сформулировать.

**Ситуация первая.** Вы заказываете в приложении доставку. В приложении есть карточка товара — с картинкой, названием, ценой и кнопкой «Купить». Вы нажимаете «Купить». Потом заказываете второй такой же товар. Потом третий. Карточка на экране одна и та же, а покупок — три, и у каждой свой номер, своя дата, свой адрес доставки. Карточка описывает, что такое товар. Покупка — это конкретная вещь с конкретными значениями.

**Ситуация вторая.** В банковском приложении есть понятие «счёт». У счёта есть номер, баланс, владелец. У вас может быть один счёт, а может быть три: зарплатный, накопительный и тот, куда вам перевели деньги за проданный велосипед. Все три устроены одинаково — у всех есть номер и баланс, — но значения у них разные.

**Ситуация третья.** Вы заполняете анкету на сайте. Анкета — это форма: поля «имя», «почта», «телефон». Вы заполняете её один раз. Ваш друг заполняет ту же самую форму — с теми же полями, в том же порядке, — но значения вводит свои. Форма одна, заполненных анкет — сколько угодно.

**Ситуация четвёртая.** Вы смотрите на чертёж дома. На нём нарисовано: две спальни, кухня, гостиная, санузел, лестница на второй этаж. По этому чертежу можно построить один дом, можно два, можно целый посёлок. Все дома будут одинаковой планировки, но в одном будут жить Ивановы, в другом — Петровы, а третий пока стоит пустой. В одном будет ремонт, в другом — обои в цветочек, в третьем — минимализм.

**Ситуация пятая.** Вы объясняете ребёнку, чем кошка отличается от собаки. Вы говорите: «У кошки есть хвост, четыре лапы, усы, и она мяукает». Это описание. А потом во дворе появляется конкретная кошка — серая, трёхцветная, с ободранным ухом, — и это уже не описание, а конкретное существо, которое мяукает под вашим окном в шесть утра.

**Ситуация шестая.** Вы впервые сталкиваетесь с кодом, в котором написано `User user = new User();`, и не понимаете: `User` — это что? Тип? Класс? Объект? Почему слово написано дважды? Что делает `new`? Зачем вообще две сущности там, где хватило бы одной?

Если последняя ситуация вам знакома — этот урок для вас. Если остальные тоже — тем лучше, значит, интуиция у вас уже есть, и осталось только связать её с синтаксисом.

## Две вещи, которые легко перепутать

В Java (и не только в ней) есть **класс** и **объект**. Это разные вещи, и путать их — самая частая ошибка у начинающих. Причём путают их не потому, что сложно, а потому, что в бытовой речи мы часто говорим «класс», имея в виду «объект», и наоборот.

**Класс** — это описание. Чертёж. Шаблон. Форма для выпечки. Он говорит: «Вот такого рода вещи существуют. У них есть такие-то поля. Они умеют делать такие-то действия». Класс — это не вещь, это **понятие о вещи**.

**Объект** — это конкретная вещь, созданная по этому описанию. Экземпляр. Дом, построенный по чертежу. Печенье, испечённое в форме. Это то, что реально существует в памяти программы прямо сейчас, у чего есть конкретные значения полей и с чем можно что-то делать.

Вот как это выглядит в коде. Класс:

```java
class User {
    String name;
    String email;
    int age;
}
```

Это описание: «Пользователь — это штука, у которой есть имя, почта и возраст». Здесь ещё нет ни одного пользователя. Здесь есть только понимание, что такое пользователь. Как чертёж дома, лежащий на столе: дом ещё не построен, но уже понятно, какой он будет.

Объект:

```java
User alice = new User();
alice.name = "Алиса";
alice.email = "alice@example.com";
alice.age = 30;
```

Вот теперь появился конкретный пользователь. Его зовут Алиса, ей тридцать, у неё есть почта. И если вы создадите второго:

```java
User bob = new User();
bob.name = "Боб";
bob.email = "bob@example.com";
bob.age = 25;
```

— это будет уже **другой** пользователь. Другой объект. У него своё имя, свой возраст, своя почта. `alice` и `bob` устроены одинаково — оба созданы по описанию `User` — но значения у них разные. Как два дома, построенных по одному чертежу: планировка одна, а жизнь внутри — разная.

## Оператор new

Ключевое слово `new` — это то, что превращает описание в вещь. Буквально: «создай мне новый объект вот такого класса».

Разберём строку по частям. Возьмём:

```java
User alice = new User();
```

Читать её нужно справа налево, и тогда всё встанет на свои места.

- `new User()` — создай новый объект класса `User`. Где-то в памяти программы появляется место, в котором лежат три поля: `name`, `email`, `age`. Пока они пустые (точнее, со значениями по умолчанию — об этом в уроке про поля и методы).
- `User alice` — объяви переменную с именем `alice`, которая может хранить ссылку на объект класса `User`.
- `=` — положи в эту переменную ссылку на только что созданный объект.

То есть в переменной `alice` лежит не сам пользователь, а **ссылка** на него. Как адрес дома в записной книжке — это не дом, а указание, где дом искать. Мы поговорим об этом подробно в пятом уроке, а пока просто запомните: `alice` — это не пользователь, это «то, по чему можно найти пользователя».

Отсюда, кстати, растёт одна странность, которая сбивает с толку почти всех. Если написать:

```java
User alice = new User();
User bob = alice;
```

— то `bob` и `alice` будут указывать на **один и тот же** объект. Не на два одинаковых, а на один. Поменяете имя через `bob` — изменится и то, что видно через `alice`. Это не баг, это следствие того, что обе переменные хранят один и тот же адрес. Подробнее — в уроке про ссылки.

А вот если написать:

```java
User alice = new User();
User bob = new User();
```

— это два разных объекта, две разные вещи, два разных адреса. Их можно менять независимо, и они друг о друге ничего не знают.

## Сколько объектов — столько и жизней

Важная мысль, которую хочется подчеркнуть: **из одного класса можно создать сколько угодно объектов**. Один, два, тысячу, миллион. Каждый будет жить своей жизнью.

Вот класс `Account` — банковский счёт:

```java
class Account {
    String number;
    double balance;
}
```

Три счёта:

```java
Account salary = new Account();
salary.number = "40817810099910004312";
salary.balance = 85_000.0;

Account savings = new Account();
savings.number = "40817810099910004313";
savings.balance = 1_200_000.0;

Account gift = new Account();
gift.number = "40817810099910004314";
gift.balance = 500.0;
```

У всех трёх есть номер и баланс. У всех трёх устройство одинаковое — потому что класс один. Но значения разные, и менять их можно по отдельности: если с зарплатного счёта уйдёт тысяча, на накопительном ничего не изменится. Это и есть смысл объектов: каждый хранит **своё** состояние, независимо от остальных.

Сравните с процедурным подходом из прошлого урока. Там была глобальная переменная `currentBalance` — одна на всех. Здесь у каждого счёта свой баланс, и путаницы не возникает просто потому, что путать нечего.

## Что ещё есть в классе, кроме полей

В наших примерах выше классы содержали только **поля** — то есть данные. Но обычно в классе есть ещё и **методы** — то есть действия, которые объект умеет выполнять.

Вот, например:

```java
class Account {
    String number;
    double balance;

    void deposit(double amount) {
        balance = balance + amount;
    }

    void withdraw(double amount) {
        if (amount > balance) {
            System.out.println("Недостаточно средств на счёте " + number);
            return;
        }
        balance = balance - amount;
    }
}
```

Теперь у объекта есть не только состояние (номер и баланс), но и поведение (положить деньги, снять деньги). И поведение работает с состоянием **того объекта**, через который его вызвали:

```java
Account salary = new Account();
salary.number = "40817810099910004312";
salary.balance = 85_000.0;

salary.deposit(15_000.0);   // на salary теперь 100 000

Account savings = new Account();
savings.number = "40817810099910004313";
savings.balance = 1_200_000.0;

savings.deposit(500.0);     // на savings теперь 1 200 500
```

Метод `deposit` написан один раз, а работает для любого объекта этого класса. При вызове `salary.deposit(...)` он берёт `balance` из `salary`, при вызове `savings.deposit(...)` — из `savings`. Об этом мы будем подробно говорить в следующем уроке, но общее представление полезно иметь уже сейчас.

Собственно, в этом и состоит главное отличие класса от простого набора переменных: класс объединяет **данные** и **действия над ними** в одно целое. Не нужно таскать данные в функцию и обратно — данные лежат там, где им место, и обрабатываются теми методами, которые написаны рядом с ними.

## Аналогия, которая помогает

Если вам нужна одна картинка, которая всё объясняет, — вот она.

**Класс — это форма для печенья.** Металлическая, с вырезанным силуэтом. Сама по себе она не печенье. Ею нельзя насытиться. Но ею можно наделать сколько угодно печений.

**Объект — это конкретное печенье.** Его можно съесть, оно имеет вкус, у него есть конкретная форма и конкретный размер (даже если форма одна и та же — тесто легло чуть иначе). Каждое печенье — отдельная вещь, хотя все они сделаны одной формой.

И ещё важное: **у каждого печенья — своя судьба**. Одно съели сразу, другое оставили на завтра, третье уронили. Форма при этом не меняется — она вообще не участвует в судьбе конкретного печенья, она только задаёт, каким оно будет.

Вот и с классами так же. Класс `User` описывает, каким бывает пользователь. Объект `alice` — это конкретная Алиса, с конкретной почтой и конкретным возрастом. Алиса может поменять почту — от этого описание «пользователь» не изменится. Может быть удалена из памяти — класс останется.

Есть ещё одно следствие этой аналогии, которое стоит проговорить. **Форма одна — а печений много, и все они разные ровно настолько, насколько разное тесто в них попало.** С классами так же: объекты одного класса отличаются друг от друга только значениями полей. Всё остальное — устройство, методы, поведение — у них общее.

## Микрозадача 1

Посмотрите на код и ответьте на два вопроса: сколько здесь классов и сколько объектов?

```java
class Book {
    String title;
    String author;
    int year;
}

Book first = new Book();
first.title = "Мастер и Маргарита";
first.author = "Булгаков";
first.year = 1967;

Book second = new Book();
second.title = "Пикник на обочине";
second.author = "Стругацкие";
second.year = 1972;

Book third = first;
```

### Разбор

**Классов здесь один** — `Book`. Он описан один раз и задаёт, что у книги есть название, автор и год.

**Объектов здесь два.** Первый создан в строке `Book first = new Book();` — это объект про «Мастера и Маргариту». Второй — в строке `Book second = new Book();` — это «Пикник на обочине».

Третья строка `Book third = first;` не создаёт новый объект. Она создаёт новую переменную `third`, которая **указывает на тот же самый объект**, что и `first`. Книг по-прежнему две, а не три. Просто у первой книги теперь два имени: `first` и `third`.

Чтобы убедиться, что это так, достаточно мысленно поменять что-нибудь через `third`:

```java
third.author = "Михаил Булгаков";
System.out.println(first.author);  // Михаил Булгаков
```

Изменилось то, что видно через `first`, — потому что `first` и `third` смотрят на один и тот же объект. Это и есть та самая особенность ссылок, о которой мы говорили выше и будем подробно говорить в пятом уроке.

## Микрозадача 2

Вот класс и код, который его использует. Найдите в этом коде ошибку — она там одна, и она концептуальная, а не синтаксическая (то есть код скомпилируется, но работает не так, как задумано).

```java
class Counter {
    int value;
}

Counter a = new Counter();
a.value = 5;

Counter b = new Counter();
b.value = 7;

Counter c = a;
c.value = 10;

System.out.println(a.value);
System.out.println(b.value);
```

Что выведется? И что, скорее всего, ожидал увидеть автор кода?

### Разбор

Выведется:

```
10
7
```

Автор кода, скорее всего, ожидал увидеть `5` и `7` — то есть думал, что `c = a` создаёт копию объекта `a`, независимую от него. Но `c = a` копирует **ссылку**, а не объект. После этой строки `a` и `c` указывают на один и тот же объект, и присваивание `c.value = 10` меняет именно его. Поэтому `a.value` тоже становится `10`.

`b` при этом не затронут — это отдельный объект, и его значение остаётся `7`.

Это классическая ошибка, и она не про невнимательность. Она про то, что в Java **объекты не копируются присваиванием**. Если вам действительно нужна копия — её надо создавать явно (об этом мы поговорим в модуле про неизменяемые объекты и `record`). Присваивание же всегда копирует только ссылку.

## Самостоятельная задача

- какие методы ему нужны (не меньше двух);

Затем ответьте на вопрос: что произойдёт, если вы создадите четвёртый объект и присвоите его переменной, которая уже указывает на первый? Изменится ли первый объект?

Готового ответа здесь не будет. Если хотите свериться с тем, как это обычно делают, — загляните в третий урок, там мы будем подробно разбирать поля и методы, и вы увидите, насколько ваша интуиция совпала с общепринятой практикой.
