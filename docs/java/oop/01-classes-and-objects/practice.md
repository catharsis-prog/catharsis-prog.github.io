# Практикум — Классы и объекты

## Как это работает

Здесь семь задач. Они идут примерно в том порядке, в котором мы проходили уроки, но постепенно усложняются: первые три — разминка, следующие три — на подумать, последняя — проектное задание, которое можно решать несколько вечеров.

Решения лежат на [отдельной странице](./practice-solutions). Сначала попробуйте сами, потом сверяйтесь. Если решение не совпало с вашим — это нормально. В ООП редко бывает один правильный ответ, и если ваш вариант работает и понятен — он тоже правильный.

Код пишите в файлах `.java`, запускайте, экспериментируйте. Читать код и писать код — это два разных навыка, и тренируются они по-разному.

## Задача 1. Прямоугольник

Создайте класс `Rectangle` с двумя полями: `width` и `height` (оба `double`). Добавьте три метода:

- `area()` — возвращает площадь;
- `perimeter()` — возвращает периметр;
- `isSquare()` — возвращает `true`, если это квадрат, и `false` в противном случае.

Создайте три разных прямоугольника: один квадрат (5×5), один вытянутый (3×7) и один «почти квадрат» (4×4.0001). Для каждого выведите площадь, периметр и ответ на вопрос «квадрат ли это».

**Что проверяется:** умеете ли вы создавать класс, объявлять поля и писать методы, которые с этими полями работают.

## Задача 2. Кофемашина

Создайте класс `CoffeeMachine` со следующим состоянием:

- `waterLevel` — уровень воды в миллилитрах (`int`);
- `beansLevel` — уровень зёрен в граммах (`int`);
- `cupsMade` — сколько чашек кофе сделано (`int`).

И поведением:

- `makeCoffee()` — пытается сварить чашку кофе. Одна чашка требует 200 мл воды и 15 г зёрен. Если ресурсов хватает — уменьшает `waterLevel` на 200, `beansLevel` на 15, увеличивает `cupsMade` на 1 и возвращает `true`. Если не хватает — ничего не меняет и возвращает `false`.
- `refillWater(int ml)` — доливает воду. Но не больше, чем до 2000 мл (это максимум бака). Если попытаться налить больше — наливает сколько влезет, остальное «выливается на пол», и метод печатает предупреждение.
- `refillBeans(int grams)` — аналогично, но максимум 500 г.
- `status()` — печатает текущее состояние: сколько воды, сколько зёрен, сколько чашек сделано.

Создайте кофемашину, залейте 500 мл воды и 100 г зёрен, сварите три чашки, выведите статус, долейте воды и снова выведите статус.

**Что проверяется:** понимаете ли вы, что методы меняют состояние **своего** объекта, и умеете ли аккуратно обращаться с ограничениями.

## Задача 3. Письмо

Создайте класс `Email` с тремя полями: `to` (адрес получателя), `subject` (тема), `body` (тело письма).

Сделайте **три конструктора**:

- `Email(String to, String subject, String body)` — полный;
- `Email(String to, String body)` — без темы, тема по умолчанию `"(без темы)"`;
- `Email(String to)` — только получатель, тема по умолчанию и тело `"(пустое письмо)"`.

Все три конструктора должны использовать `this(...)` для делегирования, чтобы логика инициализации была в одном месте.

Добавьте метод `print()`, который печатает письмо в таком формате:

```
Кому: alice@example.com
Тема: (без темы)
---
Привет!
```

Создайте три письма — полное, без темы и только с получателем — и напечатайте каждое.

**Что проверяется:** умеете ли вы писать несколько конструкторов и делегировать их друг другу, не дублируя код.

## Задача 4. Заказ с необязательным клиентом

Создайте класс `Order` с полями:

- `customerName` (`String`) — имя клиента, может быть `null`, если заказ анонимный;
- `itemCount` (`int`) — количество товаров;
- `totalPrice` (`double`) — общая стоимость.

Добавьте конструктор с тремя параметрами и метод `getCustomerDisplay()`:

- если `customerName` равен `null` — возвращает `"Гость"`;
- иначе — возвращает `customerName` (даже если это пустая строка — тогда возвращает `"(пустое имя)"`).

Добавьте метод `describe()`, который печатает что-то вроде:

```
Заказ для Гость: 3 товара на 1500.0 руб.
```

Создайте три заказа: с именем, с `null` и с пустой строкой в качестве имени. Напечатайте описания.

**Что проверяется:** понимаете ли вы, чем `null` отличается от пустой строки, и умеете ли аккуратно обрабатывать возможный `null`, не роняя программу.

## Задача 5. Билеты с номерами

Создайте класс `Ticket` с двумя полями:

- `number` (`int`) — номер билета, уникальный для каждого;
- `eventName` (`String`) — название мероприятия.

Сделайте так, чтобы при создании каждого билета ему автоматически присваивался следующий по порядку номер — начиная с 1. Для этого используйте `static`-поле-счётчик.

Добавьте метод `print()` для печати билета.

Создайте пять билетов на разные мероприятия и напечатайте их. Убедитесь, что номера идут по порядку и не повторяются.

**Дополнительный вопрос:** что произойдёт с номерами, если создать ещё один билет через полчаса после первых пяти? А если перезапустить программу? А если два билета создать в двух разных потоках?

**Что проверяется:** понимаете ли вы, что такое `static`-поле, и видите ли разницу между «одно на всех» и «своё у каждого».

## Задача 6. Найдите утечку

Вот код. Он работает, но в нём есть утечка памяти — объекты, которые уже не нужны, но не становятся мусором. Найдите утечку и объясните, как её исправить.

```java
class SessionRegistry {
    private static java.util.Map<String, Session> sessions = new java.util.HashMap<>();

    static void register(Session session) {
        sessions.put(session.getId(), session);
    }

    static Session get(String id) {
        return sessions.get(id);
    }

    static void printAll() {
        for (Session s : sessions.values()) {
            System.out.println(s);
        }
    }
}

class Session {
    private String id;
    private long createdAt;

    Session(String id) {
        this.id = id;
        this.createdAt = System.currentTimeMillis();
    }

    String getId() { return id; }

    @Override
    public String toString() {
        return "Session{" + id + "}";
    }
}
```

Подсказка: подумайте, что происходит с сессией, когда пользователь закрыл браузер и ушёл.

**Что проверяется:** понимаете ли вы, как `static`-коллекции удерживают объекты в памяти, и видите ли разницу между «объект больше не нужен» и «на объект больше нет ссылок».

## Задача 7. Проектное задание — модель библиотеки

Это большое задание. Его можно решать несколько вечеров, и оно ближе к реальной работе, чем предыдущие задачи.

Спроектируйте модель библиотеки на трёх классах: `Book`, `Reader`, `Library`.

### Book

Поля:

- `title` (`String`) — название;
- `author` (`String`) — автор;
- `isbn` (`String`) — ISBN;
- `available` (`boolean`) — свободна ли книга.

Методы:

- конструктор с тремя параметрами (название, автор, ISBN), при этом `available = true`;
- `checkout()` — выдаёт книгу. Если книга уже выдана — возвращает `false` и ничего не делает. Если свободна — ставит `available = false` и возвращает `true`;
- `returnBook()` — возвращает книгу. Если книга и так свободна — возвращает `false`. Иначе ставит `available = true` и возвращает `true`;
- `isAvailable()` — возвращает текущее значение `available`;
- геттеры для `title`, `author`, `isbn`;
- `toString()`, который печатает что-то вроде `"Мастер и Маргарита (Булгаков) [ISBN: 978-5-..."`.

### Reader

Поля:

- `name` (`String`) — имя читателя;
- `ticketNumber` (`int`) — номер билета, автоматически присваивается при создании (начиная с 1, через `static`-счётчик);
- `borrowedBooks` (`java.util.List<Book>`) — список выданных книг (не больше 5 одновременно).

Методы:

- конструктор с именем;
- `borrow(Book book)` — пытается взять книгу. Если у читателя уже 5 книг — возвращает `false` и печатает «Лимит книг исчерпан». Если книга недоступна (уже выдана) — возвращает `false` и печатает «Книга недоступна». Иначе вызывает `book.checkout()`, добавляет книгу в `borrowedBooks` и возвращает `true`;
- `giveBack(Book book)` — возвращает книгу. Если книги нет в списке — возвращает `false`. Иначе вызывает `book.returnBook()`, удаляет из списка и возвращает `true`;
- `getBorrowedCount()` — сколько книг на руках;
- `toString()` — имя, номер билета, сколько книг на руках.

### Library

Поля:

- `books` (`java.util.List<Book>`) — все книги в библиотеке;
- `readers` (`java.util.List<Reader>`) — все читатели.

Методы:

- `addBook(Book book)` — добавляет книгу в каталог;
- `registerReader(String name)` — создаёт читателя и добавляет в список, возвращает созданного читателя;
- `findBookByIsbn(String isbn)` — ищет книгу по ISBN, возвращает `null`, если не найдена;
- `lendBook(Reader reader, String isbn)` — находит книгу по ISBN и пытается выдать её читателю. Если книга не найдена — печатает ошибку и возвращает `false`. Иначе вызывает `reader.borrow(book)` и возвращает результат;
- `acceptReturn(Reader reader, String isbn)` — находит книгу и возвращает её от читателя. Аналогично с ошибками;
- `printCatalog()` — печатает все книги с пометкой «свободна» или «выдана»;
- `printReaders()` — печатает всех читателей.

### Сценарий проверки

Напишите `main`, который:

1. Создаёт библиотеку.
2. Добавляет в неё пять книг (любых, реальных или выдуманных).
3. Регистрирует двух читателей — Алису и Боба.
4. Алиса берёт две книги, Боб — одну.
5. Печатает каталог: три книги должны быть помечены как выданные, две — как свободные.
6. Печатает читателей: у Алисы две книги, у Боба одна.
7. Алиса пытается взять ту же книгу, что уже взяла, — должна получить отказ «Книга недоступна».
8. Алиса возвращает одну книгу.
9. Печатает каталог: теперь четыре книги свободны, одна выдана.
10. Боб пытается взять книгу, которую только что вернула Алиса, — должен получить согласие.
11. Печатает читателей: у Алисы одна книга, у Боба две.

### Дополнительные требования

- Поля классов — `private`, доступ только через методы. Мы ещё не проходили инкапсуляцию в этом модуле, но `private` — это хорошая привычка с самого начала.
- Везде, где нужно, обрабатывайте `null`: если `findBookByIsbn` вернул `null` — не вызывайте у него методы, а печатайте ошибку.
- `Reader` и `Library` не должны ломаться, если им передали `null` в качестве аргумента. В этом случае возвращайте `false` или печатайте ошибку.

**Что проверяется:** всё сразу. Умение проектировать классы, писать конструкторы, использовать `static`, аккуратно обращаться со ссылками и `null`, и — главное — умение собрать из этого работающую систему.
