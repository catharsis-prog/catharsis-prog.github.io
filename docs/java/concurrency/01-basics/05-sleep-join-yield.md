# 1.5. sleep(), join(), yield()

## Где вы это уже видели

Три метода, о которых пойдёт речь, — это три способа сказать потоку: «подожди». Но ждут они по-разному, и путать их не следует.

**Будильник.** Вы поставили будильник на десять минут и прилегли. Вы не работаете, но и не ушли — вы в комнате, просто спите. Через десять минут встанете сами. Это `sleep()`.

**Совместная работа.** Вы делаете отчёт вместе с коллегой. Ваша часть готова, а его ещё нет. Вы не можете отправить отчёт, пока он не закончит. Вы сидите и ждёте, пока он не скажет: «готово». Это `join()`.

**Уступка места.** Вы стоите в очереди и видите, что за вами человек торопится. Вы говорите: «проходите, я подожду». Может, он пройдёт, а может, и нет — очередь не обязана вас слушать. Это `yield()`.

## Теория

### sleep() — пауза на заданное время

`Thread.sleep(millis)` усыпляет текущий поток на указанное число миллисекунд. Поток переходит в состояние `TIMED_WAITING` и просыпается сам, когда время выйдет.

```java
try {
    Thread.sleep(1000); // спать одну секунду
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
}
```

Несколько важных деталей.

**Первое: `sleep()` не отпускает монитор.** Если вы спите внутри `synchronized`-блока, монитор остаётся за вами. Все остальные потоки, которым нужен этот монитор, будут стоять в `BLOCKED`, пока вы не проснётесь и не выйдете из блока. Это классическая ошибка: уснуть в критической секции и удивляться, почему программа висит.

```java
synchronized (lock) {
    Thread.sleep(5000); // все остальные ждут эти пять секунд
}
```

**Второе: `sleep()` можно прервать.** Если другой поток вызовет `interrupt()` на спящем потоке, `sleep()` бросит `InterruptedException`. Это не сбой — это способ разбудить поток, когда он больше не нужен. Подробно о прерывании — в следующей главе.

**Третье: точность не гарантирована.** `sleep(100)` означает «не меньше ста миллисекунд». Реально поток может проспать сто десять или сто пятьдесят — зависит от планировщика и нагрузки на систему. Если вам нужна точность до миллисекунды — `sleep()` не ваш инструмент.

**Четвёртое: `sleep()` — статический метод.** Он всегда усыпляет **текущий** поток, а не тот, у которого вы его вызвали. Запись `thread.sleep(1000)` не усыпит `thread` — она усыпит того, кто её вызвал. Это ещё одна классическая ловушка.

### join() — дождаться завершения другого потока

`thread.join()` заставляет текущий поток ждать, пока `thread` не завершится. Это основной способ синхронизировать завершение работы.

```java
Thread worker = new Thread(() -> {
    System.out.println("Работаю");
    try {
        Thread.sleep(1000);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
    System.out.println("Закончил");
});

worker.start();
worker.join(); // главный поток ждёт, пока worker не завершится
System.out.println("main продолжает");
```

**Вывод:**

```text
Работаю
Закончил
main продолжает
```

Без `join()` строка `main продолжает` напечаталась бы раньше, чем `Закончил`.

Три важные детали про `join()`.

**Первое: `join()` без таймаута переводит поток в `WAITING`.** Поток не проснётся сам — только когда целевой поток завершится. Если целевой поток никогда не завершится, `join()` будет ждать вечно.

**Второе: `join(timeout)` переводит поток в `TIMED_WAITING`.** Ждёт не дольше указанного времени. Если поток не завершился за это время — `join()` возвращает управление, и вы можете проверить, жив ли он ещё, через `thread.isAlive()`.

```java
worker.join(500); // ждать не больше полусекунды
if (worker.isAlive()) {
    System.out.println("Не успел, работаю дальше");
}
```

**Третье: `join()` можно прервать.** Как и `sleep()`, `join()` бросает `InterruptedException`, если поток, который ждёт, прервут.

**Четвёртое: если поток уже завершён, `join()` возвращается сразу.** Это удобно: не нужно проверять состояние перед вызовом.

### yield() — вежливая просьба уступить место

`Thread.yield()` говорит планировщику: «я не против, если ты дашь поработать другому потоку». Это не команда, а рекомендация. Планировщик может её проигнорировать.

```java
Thread.yield(); // планировщик может передать CPU другому потоку, а может и нет
```

И вот тут начинается самое интересное. **`yield()` почти бесполезен на практике.** Почему?

- **Нет гарантий.** Планировщик не обязан реагировать. В некоторых реализациях JVM `yield()` вообще ничего не делает.
- **Нет предсказуемости.** Даже если планировщик отреагирует, вы не знаете, какому потоку достанется процессор и насколько долго.
- **Есть лучшие инструменты.** Если вам нужно, чтобы поток подождал — используйте `sleep()`. Если нужно синхронизировать работу — используйте `join()`, `wait()`, `Lock`. Если нужно управлять нагрузкой — используйте пулы потоков.

`yield()` встречается в учебниках, потому что он есть в API. В реальном коде его используют крайне редко — обычно в низкоуровневых оптимизациях или в тестах, где нужно «немного уступить». Для 99% задач это не тот инструмент.

### Сводная таблица

| Метод | Что делает | Состояние | Отпускает монитор | Можно прервать |
|---|---|---|---|---|
| `sleep(ms)` | Спит заданное время | `TIMED_WAITING` | Нет | Да |
| `join()` | Ждёт завершения потока | `WAITING` | Нет | Да |
| `join(ms)` | Ждёт завершения не дольше `ms` | `TIMED_WAITING` | Нет | Да |
| `yield()` | Просит уступить CPU | `RUNNABLE` | Нет | Нет |

## Микрозадача 1: sleep() в главном потоке

**Задача:** Напишите программу, которая печатает «Начало», спит две секунды и печатает «Конец». Замерьте реальное время сна.

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        long start = System.currentTimeMillis();
        System.out.println("Начало");
        Thread.sleep(2000);
        System.out.println("Конец");
        long elapsed = System.currentTimeMillis() - start;
        System.out.println("Прошло: " + elapsed + " мс");
    }
}
```

**Возможный вывод:**

```text
Начало
Конец
Прошло: 2003 мс
```

**Разбор:** `sleep(2000)` усыпил главный поток на две секунды. Реально прошло чуть больше — 2003 миллисекунды. Это те самые накладные расходы, о которых мы говорили: `sleep()` гарантирует «не меньше», а не «ровно». Если запустить программу на загруженной машине, можно увидеть 2050 или даже 2100 мс.

## Микрозадача 2: join() ждёт завершения

**Задача:** Создайте поток, который печатает числа от 1 до 5 с паузой в полсекунды. Дождитесь его завершения через `join()` и только потом напечатайте «Готово».

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread counter = new Thread(() -> {
            for (int i = 1; i <= 5; i++) {
                System.out.println(i);
                try {
                    Thread.sleep(500);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
        });

        counter.start();
        counter.join();
        System.out.println("Готово");
    }
}
```

**Вывод:**

```text
1
2
3
4
5
Готово
```

**Разбор:** без `join()` строка «Готово» напечаталась бы почти сразу после `1`, потому что `start()` возвращает управление немедленно. `join()` заставил главный поток ждать, пока `counter` не завершится. Обратите внимание: `join()` не усыпляет поток на фиксированное время — он ждёт именно события «поток завершился». Если поток отработает за сто миллисекунд, `join()` вернётся через сто миллисекунд.
