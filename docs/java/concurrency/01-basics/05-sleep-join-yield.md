# 1.6. Прерывание потоков

## Где вы это уже видели

**Звонок в дверь.** Вы спите. Звонит будильник — вы встаёте. Но если кто-то позвонит в дверь раньше будильника, вы тоже проснётесь — не потому, что время вышло, а потому, что вас позвали. Разбудить можно двумя способами: дождаться своего часа или получить сигнал. `sleep()` — это первый. `interrupt()` — второй.

**Разговор по телефону.** Вы говорите, а собеседник вдруг перебивает: «извини, я на встречу опаздываю, давай потом». Вы не стали ждать, пока он закончит мысль, — вы получили сигнал «прерви разговор», и завершили его сами. Сигнал — не приказ. Вам решать, как на него реагировать.

**Работа в офисе.** Начальник заходит и говорит: «сворачивайся, через пять минут совещание». Он не вырывает у вас из рук документ. Он подаёт сигнал, а вы уже сами решаете, дописывать ли абзац или сохранить и закрыть.

**Поток в Java.** У вас есть фоновый поток, который качает данные. Пользователь закрыл приложение. Поток нужно остановить. Но остановить его насильно — плохая идея: он может быть посреди записи файла, и вы получите битый файл. Поэтому Java не останавливает потоки силой. Она **просит их остановиться** — а поток сам решает, когда и как это сделать.

Именно поэтому есть `interrupt()` и всё, что с ним связано. Это не «выключить поток», это «попросить поток, чтобы он подумал о завершении».

## Теория

### Флаг прерывания

У каждого объекта `Thread` есть внутренний флаг — **флаг прерывания**. Это просто булево значение, `true` или `false`. Изначально `false`.

Когда вы вызываете `thread.interrupt()`, происходит три вещи в зависимости от состояния потока.

1. **Если поток в `RUNNABLE` и работает** — флаг прерывания просто выставляется в `true`. Поток продолжает работать, но теперь он может проверить флаг и решить, что делать. Ничего не прерывается само по себе.
2. **Если поток в `WAITING` или `TIMED_WAITING`** — то есть в `sleep()`, `join()`, `wait()` — поток просыпается, флаг прерывания **сбрасывается**, и метод бросает `InterruptedException`.
3. **Если поток уже в `TERMINATED`** — ничего не происходит. Выставить флаг у мёртвого потока нельзя, но `interrupt()` не бросит исключения — просто тихо ничего не сделает.

Ключевая мысль: **`interrupt()` не останавливает поток**. Он только подаёт сигнал. Поток остановится сам, если захочет.

### Как проверить флаг

У `Thread` есть два метода для работы с флагом.

**`Thread.currentThread().isInterrupted()`** — проверяет флаг и **не сбрасывает** его. Возвращает `true`, если флаг установлен. Поток остаётся «помеченным».

**`Thread.interrupted()`** — статический метод. Проверяет флаг текущего потока **и сбрасывает** его в `false`. Если флаг был `true`, вернёт `true` и сбросит; при следующем вызове вернёт `false`.

Разница тонкая, но важная. Статический `Thread.interrupted()` «съедает» флаг — после него сигнал потерян. Поэтому в большинстве случаев используют `isInterrupted()` — он не «съедает».

<div style="background-color: #1E0F33; border-left: 4px solid #B388FF; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #B388FF;">Правило:</strong> используйте <code>Thread.currentThread().isInterrupted()</code> в своих проверках. <code>Thread.interrupted()</code> нужен реже — когда вы сознательно хотите «погасить» сигнал после обработки.
</div>

### InterruptedException — что это такое

`InterruptedException` — это **не ошибка**. Это сообщение: «пока ты спал, кто-то тебя прервал». Обычно это означает, что пора сворачиваться.

`InterruptedException` бросают методы, которые блокируют поток с возможностью прерывания: `sleep()`, `join()`, `wait()`, `park()`, `await()` и другие.

Важная деталь: **при броске `InterruptedException` флаг прерывания сбрасывается**. То есть если вы поймали исключение, но ничего не сделали — сигнал потерян. И это уже ошибка.

### Правильная обработка InterruptedException

Есть три сценария, и в каждом — свой правильный ответ.

**Сценарий 1: вы не можете пробросить исключение дальше.** Например, `run()` интерфейса `Runnable` не объявляет никаких исключений, значит, `InterruptedException` пробросить из него нельзя. Правильная обработка в этом случае:

```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt(); // восстановить флаг
    return; // завершить работу
}
```

Почему восстанавливать флаг? Потому что иначе сигнал «прервись» потеряется. Если ваш поток вызывается из другого кода, этот код больше не узнает, что вас прерывали. Восстановление флага — это способ **передать сигнал дальше**.

**Сценарий 2: вы можете пробросить исключение.** Например, внутри метода, который уже объявляет `throws InterruptedException`. Тогда просто пробрасывайте:

```java
public void doWork() throws InterruptedException {
    Thread.sleep(1000);
}
```

**Сценарий 3: вы получили сигнал, обработали его и завершаетесь.** В этом случае можно не восстанавливать флаг, но нужно выйти из метода или цикла.

```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    System.out.println("Меня прервали, выхожу");
    return;
}
```

Главное — не «проглатывать» исключение молча. Пустой `catch` с комментарием «ничего не делаем» — это баг. Вы получили сигнал остановиться и его проигнорировали.

### Проверка флага в долгих циклах

Если поток работает в долгом цикле без блокирующих методов — `sleep()`, `wait()` — то `interrupt()` не бросит исключения. Флаг просто выставится, и поток про него не узнает, пока сам не проверит.

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                // какая-то работа
            }
            System.out.println("Поток завершается по прерыванию");
        });

        worker.start();
        Thread.sleep(100);
        worker.interrupt();
        worker.join();
    }
}
```

**Правило:** если ваш поток работает долго и не вызывает блокирующих методов — **проверяйте флаг сами**, регулярно, в каждой итерации цикла. Иначе `interrupt()` ни на что не повлияет.

### Чего делать НЕЛЬЗЯ

В Java есть устаревшие методы `Thread.stop()`, `Thread.suspend()` и `Thread.resume()`. Они помечены как `@Deprecated` и **не должны использоваться**. Причины:

- **`stop()`** освобождает все мониторы, которые держал поток, в произвольный момент. Это ломает инварианты объектов: например, объект может остаться в промежуточном состоянии. Следующий поток, который его прочитает, увидит мусор.
- **`suspend()` и `resume()`** могут привести к дедлоку: если поток остановили, пока он держал монитор, никто больше этот монитор не получит.

Вместо них — `interrupt()` и добровольное завершение потока. Медленнее, но безопасно.

<div style="background-color: #251445; border-left: 4px solid #00E5D1; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #00E5D1;">Важно:</strong> <code>Thread.stop()</code> не просто устарел — он опасен. Код с <code>stop()</code> может проработать годы и упасть в самый неподходящий момент. Не используйте его. Никогда.
</div>

### Аналогия с просьбой

Вернёмся к звонку в дверь. `interrupt()` — это не «выломать дверь и вытащить человека на улицу». Это «позвонить в дверь и сказать: пора». Что человек сделает — откроет, скажет «ещё пять минут» или притворится, что не слышит, — зависит от него. Но если он разумный, он соберётся и выйдет.

А `stop()` — это именно выломать дверь. Иногда работает, но чаще — бьёт посуду и пугает кота.

## Микрозадача 1: прервать спящий поток

**Задача:** Создайте поток, который спит десять секунд. Из главного потока прервите его через одну секунду. Убедитесь, что поток проснулся раньше и корректно обработал прерывание.

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread sleeper = new Thread(() -> {
            System.out.println("Засыпаю на 10 секунд");
            try {
                Thread.sleep(10000);
            } catch (InterruptedException e) {
                System.out.println("Меня прервали, встаю");
                Thread.currentThread().interrupt(); // восстановить флаг
                return;
            }
            System.out.println("Проснулся сам");
        });

        sleeper.start();
        Thread.sleep(1000);
        System.out.println("Прерываю");
        sleeper.interrupt();
        sleeper.join();
        System.out.println("Готово");
    }
}
```

**Вывод:**

```text
Засыпаю на 10 секунд
Прерываю
Меня прервали, встаю
Готово
```

**Разбор:** поток заснул на десять секунд, но через одну секунду получил `interrupt()`. `sleep()` бросил `InterruptedException`, поток поймал его, вывел сообщение, восстановил флаг и завершился. `join()` в главном потоке дождался этого завершения. Обратите внимание: десять секунд не прошли — поток проснулся по сигналу, а не по времени.

## Микрозадача 2: проверка флага в цикле

**Задача:** Создайте поток, который в цикле увеличивает счётчик и проверяет флаг прерывания. Прервите его через сто миллисекунд и убедитесь, что он завершился.

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread counter = new Thread(() -> {
            long count = 0;
            while (!Thread.currentThread().isInterrupted()) {
                count++;
            }
            System.out.println("Посчитал до: " + count);
        });

        counter.start();
        Thread.sleep(100);
        counter.interrupt();
        counter.join();
    }
}
```

**Возможный вывод:**

```text
Посчитал до: 213456789
```

**Разбор:** поток крутился в цикле без блокирующих методов. `interrupt()` не бросил исключения — он только выставил флаг. Поток увидел флаг в условии `while` и вышел из цикла. Если бы проверки флага не было — поток крутился бы вечно, и никакой `interrupt()` бы не помог. Это и есть та самая ответственность: **поток сам решает, когда остановиться**.

Требования:

1. Если поток прерывают — он должен вывести «Загрузка отменена на N%» и корректно завершиться, восстановив флаг прерывания.
2. Если загрузка доходит до конца — вывести «Загрузка завершена».
3. В главном потоке: запустить загрузку, подождать три секунды, прервать поток и дождаться его завершения через `join()`.

## 📌 Что дальше

В следующей главе — **«Имена, приоритеты, `currentThread()`»**. Разберём, как отличить один поток от другого, зачем давать потокам имена и почему приоритеты — инструмент, которому доверять не стоит.
