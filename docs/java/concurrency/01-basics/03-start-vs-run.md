# 1.3. start() vs run()

## Где вы это уже видели

Три положения, каждому знакомые. И во всех трёх — одна и та же ошибка, только с разных сторон.

**Положение первое.** Написали код с потоком. Запускают — всё вроде работает, но дела выполняются строго по очереди, никакой параллельности. Смотрят в код: объект `Thread` создан, задача описана. А потом замечают, что вместо `start()` стоит `run()`. Бумагу написали, а писца не позвали. Сами всё и сделали, своими руками, и удивляются, отчего устали.

**Положение второе.** Хотят запустить одну и ту же задачу дважды. Пишут `thread.start(); thread.start();` — и программа падает с `IllegalThreadStateException`. Что именно пошло не так — непонятно. Писца позвали, он отработал смену, а его снова зовут. Да он уже домой ушёл.

**Положение третье.** Говорили им: «нельзя вызывать `run()` напрямую». Они запомнили, но не поняли: `run()` же обычный метод, почему его нельзя вызвать? И вызывают. И получают не то, чего хотели, хотя формально всё правильно.

Все три положения — про одну и ту же вещь: разницу между `start()` и `run()`. Разберём её как следует, не спеша.

## Теория

### run() — это просто метод

`run()` — обычный метод. Никакой магии в нём нет, никакого особого значения. Если вы вызываете его из `main`, он выполняется в потоке `main`, как любой другой метод. Как если бы вы сами сели и написали бумагу, вместо того чтобы поручить её писцу.

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(
            () -> System.out.println("Я в потоке " + Thread.currentThread().getName())
        );
        thread.run();
    }
}
```

**Вывод:**

```text
Я в потоке main
```

Обратите внимание: мы создали объект `Thread`, вызвали у него метод `run()` — а имя потока всё равно `main`. Новый поток не появился. Мы просто выполнили кусок кода в текущем потоке. Писца наняли, жалованье положили, а бумагу сами написали. И вышло, что жалованье заплатили дважды — за писца и за себя.

### start() — это команда

`start()` устроен иначе. Это не просто метод, который что-то делает. Это команда операционной системе и JVM: создай новый поток и начни выполнять в нём метод `run()` этого объекта. То есть — позови писца и вели ему писать.

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(
            () -> System.out.println("Я в потоке " + Thread.currentThread().getName())
        );
        thread.start();
    }
}
```

**Вывод:**

```text
Я в потоке Thread-0
```

Имя уже другое. Мы запустили новый поток, и код выполнился в нём. Писец пришёл, сел, написал. Вы в это время могли заниматься своими делами — и занимались, потому что `start()` не ждёт.

### Аналогия

Представьте, что вам нужно помыть посуду.

**`run()`** — вы сами идёте на кухню и моете. Работа сделана, но вы были заняты всё это время. Никакой параллельности, никакого писца.

**`start()`** — вы зовёте соседа по комнате и просите его помыть посуду. Работа тоже сделана, но вы уже занимаетесь своими делами параллельно. Сосед, впрочем, может и отказаться — но это уже другой разговор.

Разница кажется очевидной. Но именно её путают чаще всего, потому что оба метода «делают одно и то же» — выполняют описанную в `run()` работу. Разница только в том, **где** эта работа происходит: у вас на глазах или в соседней комнате.

### start() возвращает управление сразу

Ещё одна важная деталь: `start()` не ждёт, пока поток завершится. Он запускает поток и сразу возвращает управление дальше по коду. Как вы, позвав соседа мыть посуду, не стоите над ним, а идёте заниматься своими делами.

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread thread = new Thread(() -> {
            try {
                Thread.sleep(2000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
            System.out.println("Поток закончил");
        });
        thread.start();
        System.out.println("main закончил");
    }
}
```

**Вывод** почти наверняка:

```text
main закончил
Поток закончил
```

Причина проста: `start()` вернул управление немедленно. `main` напечатал свою строку и завершился, а поток ещё спал две секунды. Как хозяин, который распорядился и ушёл, а прислуга ещё возится. Как дождаться её — разберём в главе про `join()`.

### Почему повторный start() падает

Объект `Thread` — одноразовый. Как билет на сеанс. После вызова `start()` поток начинает свой жизненный цикл: сначала `NEW`, потом `RUNNABLE`, потом `TERMINATED`. Запустить его ещё раз нельзя: системный поток, который за ним стоял, уже отработал и уничтожен.

```java
Thread thread = new Thread(() -> System.out.println("Работаю"));
thread.start();
thread.start();
```

**Вывод** (порядок строк может варьироваться):

```text
Работаю
Exception in thread "main" java.lang.IllegalThreadStateException
```

Только параллельности вы при этом не получите. Как бумагу можно переписывать хоть десять раз, а писца при этом не звать.

### Что будет, если вызвать run() дважды

Ничего страшного. Код просто выполнится дважды подряд в текущем потоке. Никаких исключений, никакой параллельности.

```java
Thread thread = new Thread(() -> System.out.println("Работаю"));
thread.run();
thread.run();
```

**Вывод:**

```text
Работаю
Работаю
```

Оба раза — в потоке `main`. Программа честно делает то, что вы написали. Просто не то, чего вы хотели. Как если бы вы дважды сами переписали бумагу, ни разу не позвав писца, — и потом удивлялись, отчего это вас так утомило.

### Как запустить одну задачу дважды

Распространённое заблуждение: «`Thread` одноразовый, значит, задачу нельзя запустить дважды». Это неверно. Одноразовый — конкретный объект `Thread`, но не задача. Чтобы запустить ту же работу второй раз, создайте новый `Thread` с тем же `Runnable`:

```java
Runnable task = () -> System.out.println("Работаю в потоке " + Thread.currentThread().getName());
new Thread(task).start();
new Thread(task).start();
```

**Возможный вывод:**

```text
Работаю в потоке Thread-0
Работаю в потоке Thread-1
```

Два разных потока выполняют одну и ту же задачу. Именно поэтому в предыдущей главе мы оформляли задачу как `Runnable`, а не как наследника `Thread`: задача переиспользуется, а исполнитель создаётся под каждый запуск. Один и тот же приказ можно отдать разным писцам — приказ от этого не портится.

### Состояния потока кратко

Подробно о жизненном цикле — в следующей главе, но одно нужно знать уже сейчас. У потока есть состояния, и `start()` — единственный способ перевести его из `NEW` в `RUNNABLE`.

```text
NEW ──── start() ────▶ RUNNABLE ──── ... ────▶ TERMINATED
```

Пока поток в состоянии `NEW` — `start()` сработает. Как только он вышел из `NEW` — уже нет, будет исключение. Как с билетом: пока не пробили — можно войти; пробили — извините.

## Микрозадача 1: run() вместо start()

**Задача:** Создайте поток и вызовите у него `run()` вместо `start()`. Убедитесь, что новый поток не появился.

**Решение:**

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(
            () -> System.out.println("Я в потоке " + Thread.currentThread().getName())
        );
        thread.run();
    }
}
```

**Вывод:**

```text
Я в потоке main
```

**Разбор:** мы создали объект `Thread`, но вызвали `run()` напрямую. Это обычный вызов метода в текущем потоке. Нового потока не появилось. Программа выполняется последовательно. Если бы мы написали `thread.start()` — вывод был бы `Я в потоке Thread-0`, и работа выполнялась бы в новом потоке. Ошибка эта коварна тем, что программа не падает и даже выдаёт результат. Только результат этот не тот, что вы планировали. Писца наняли, а бумагу сами написали. И то сказать — бумага-то написана, чего ещё желать? А того, что писец без дела сидит и жалованье получает.

## Микрозадача 2: повторный start()

**Задача:** Запустите один и тот же объект `Thread` дважды через `start()` и посмотрите, что произойдёт.

**Решение:**

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(() -> System.out.println("Работаю"));
        thread.start();
        thread.start();
    }
}
```

**Вывод** (порядок строк может варьироваться):

```text
Работаю
Exception in thread "main" java.lang.IllegalThreadStateException
```

**Разбор:** первый `start()` перевёл поток из `NEW` в `RUNNABLE` — поток выполнился. Второй `start()` увидел, что поток уже не в `NEW`, и выбросил `IllegalThreadStateException`. Причём это исключение возникло в потоке `main`, а не в рабочем потоке. Первый поток при этом свою работу выполнил нормально — то есть вторая попытка запуска уронила `main`, но не первый поток. Как если бы вы позвали писца во второй раз, а он уже домой ушёл, и вы стоите с бумагой в руке и с конфузом.

## 🎯 Самостоятельная задача

Напишите `Runnable`, который выводит имя текущего потока. Затем:

1. Вызовите `run()` на двух разных объектах `Thread`, передав им один и тот же `Runnable`. Сравните имена потоков.
2. Создайте ещё два новых `Thread` с тем же `Runnable` и запустите их через `start()`. Сравните имена потоков.
3. Попробуйте повторно вызвать `start()` на уже запущенном `Thread`. Обработайте исключение в `try/catch` и выведите понятное сообщение вместо стандартного стектрейса.
