# 1.3. start() vs run()

## Где вы это уже видели

**Симптом первый.** Вы написали код с потоком. Запускаете — всё вроде работает, но задачи выполняются строго по очереди, никакой параллельности. Смотрите в код: объект `Thread` создан, задача описана. А потом замечаете, что вместо `start()` стоит `run()`.

**Симптом второй.** Вы хотите запустить одну и ту же задачу дважды. Пишете `thread.start(); thread.start();` — и программа падает с `IllegalThreadStateException`. Что именно пошло не так — непонятно.

**Симптом третий.** Вам говорили «нельзя вызывать `run()` напрямую». Вы запомнили, но не поняли: `run()` же обычный метод, почему его нельзя вызвать?

Все три симптома про одну и ту же вещь — разницу между `start()` и `run()`. Разберём её как следует.

## Теория

### run() — это просто метод

`run()` — обычный метод. Никакой магии в нём нет. Если вы вызываете его из `main`, он выполняется в потоке `main`, как любой другой метод.

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(
            () -> System.out.println("Я в потоке " + Thread.currentThread().getName())
        );
        thread.run();
    }
}
```

**Вывод:**

```text
Я в потоке main
```

Обратите внимание: мы создали объект `Thread`, вызвали у него метод `run()` — а имя потока всё равно `main`. Новый поток не появился. Мы просто выполнили кусок кода в текущем потоке.

### start() — это команда JVM

`start()` устроен иначе. Это не просто метод, который что-то делает. Это команда операционной системе и JVM: создай новый системный поток и начни выполнять в нём метод `run()` этого объекта.

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(
            () -> System.out.println("Я в потоке " + Thread.currentThread().getName())
        );
        thread.start();
    }
}
```

**Вывод:**

```text
Я в потоке Thread-0
```

Имя уже другое. Мы запустили новый поток, и код выполнился в нём.

### Аналогия

Представьте, что вам нужно помыть посуду.

**`run()`** — вы сами идёте на кухню и моете. Работа сделана, но вы были заняты всё это время.

**`start()`** — вы зовёте соседа по комнате и просите его помыть посуду. Работа тоже сделана, но вы уже занимаетесь своими делами параллельно.

Разница кажется очевидной. Но именно её путают чаще всего, потому что оба метода «делают одно и то же» — выполняют описанную в `run()` работу. Разница только в том, где эта работа происходит.

### start() возвращает управление сразу

Ещё одна важная деталь: `start()` не ждёт, пока поток завершится. Он запускает поток и сразу возвращает управление дальше по коду.

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread thread = new Thread(() -> {
            try {
                Thread.sleep(2000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
            System.out.println("Поток закончил");
        });
        thread.start();
        System.out.println("main закончил");
    }
}
```

**Вывод** почти наверняка:

```text
main закончил
Поток закончил
```

Причина: `start()` вернул управление немедленно. `main` напечатал свою строку и завершился, а поток ещё спал две секунды. Как дождаться его завершения — разберём в главе про `join()`.

### Почему повторный start() падает

Объект `Thread` — одноразовый. После вызова `start()` поток начинает свой жизненный цикл: сначала `NEW`, потом `RUNNABLE`, потом `TERMINATED`. Запустить его ещё раз нельзя: системный поток, который за ним стоял, уже отработал и уничтожен.

```java
Thread thread = new Thread(() -> System.out.println("Работаю"));
thread.start();
thread.start();
```

**Вывод** (порядок строк может варьироваться):

```text
Работаю
Exception in thread "main" java.lang.IllegalThreadStateException
```

  <strong style="color: #00E5D1;">Важно:</strong> одноразовость касается именно <code>start()</code>. Метод <code>run()</code> можно вызывать сколько угодно раз — это же обычный метод. Только параллельности вы при этом не получите.

### Что будет, если вызвать run() дважды

Ничего страшного. Код просто выполнится дважды подряд в текущем потоке. Никаких исключений, никакой параллельности.

```java
Thread thread = new Thread(() -> System.out.println("Работаю"));
thread.run();
thread.run();
```

**Вывод:**

```text
Работаю
Работаю
```

Оба раза — в потоке `main`. Программа честно делает то, что вы написали. Просто не то, чего вы хотели.

### Как запустить одну задачу дважды

Распространённое заблуждение: «`Thread` одноразовый, значит, задачу нельзя запустить дважды». Это неверно. Одноразовый — конкретный объект `Thread`, но не задача. Чтобы запустить ту же работу второй раз, создайте новый `Thread` с тем же `Runnable`:

```java
Runnable task = () -> System.out.println("Работаю в потоке " + Thread.currentThread().getName());
new Thread(task).start();
new Thread(task).start();
```

**Возможный вывод:**

```text
Работаю в потоке Thread-0
Работаю в потоке Thread-1
```

Два разных потока выполняют одну и ту же задачу. Именно поэтому в предыдущей главе мы оформляли задачу как `Runnable`, а не как наследника `Thread`: задача переиспользуется, а исполнитель создаётся под каждый запуск.

### Состояния потока кратко

Подробно о жизненном цикле — в следующей главе, но одно нужно знать уже сейчас. У потока есть состояния, и `start()` — единственный способ перевести его из `NEW` в `RUNNABLE`.

```text
NEW ──── start() ────▶ RUNNABLE ──── ... ────▶ TERMINATED
```

Пока поток в состоянии `NEW` — `start()` сработает. Как только он вышел из `NEW` — уже нет, будет исключение.

## Микрозадача 1: run() вместо start()

**Задача:** Создайте поток и вызовите у него `run()` вместо `start()`. Убедитесь, что новый поток не появился.

**Решение:**

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(
            () -> System.out.println("Я в потоке " + Thread.currentThread().getName())
        );
        thread.run();
    }
}
```

**Вывод:**

```text
Я в потоке main
```

**Разбор:** мы создали объект `Thread`, но вызвали `run()` напрямую. Это обычный вызов метода в текущем потоке. Нового потока не появилось. Программа выполняется последовательно. Если бы мы написали `thread.start()` — вывод был бы `Я в потоке Thread-0`, и работа выполнялась бы в новом потоке. Ошибка эта коварна тем, что программа не падает и даже выдаёт результат. Только результат этот не тот, что вы планировали.

## Микрозадача 2: повторный start()

**Задача:** Запустите один и тот же объект `Thread` дважды через `start()` и посмотрите, что произойдёт.

**Решение:**

```java
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(() -> System.out.println("Работаю"));
        thread.start();
        thread.start();
    }
}
```

**Вывод** (порядок строк может варьироваться):

```text
Работаю
Exception in thread "main" java.lang.IllegalThreadStateException
```

**Разбор:** первый `start()` перевёл поток из `NEW` в `RUNNABLE` — поток выполнился. Второй `start()` увидел, что поток уже не в `NEW`, и выбросил `IllegalThreadStateException`. Причём это исключение возникло в потоке `main`, а не в рабочем потоке. Первый поток при этом свою работу выполнил нормально — то есть вторая попытка запуска уронила `main`, но не первый поток.
