# 1.7. Имена, приоритеты, currentThread()

## Где вы это уже видели

**Позывной в рации.** На стройке или на корабле у каждого свой позывной: «Сокол», «Бриз», «Вышка». Когда в эфире звучит «Вышка, ответь», — сразу понятно, к кому обращаются. Без позывных было бы «эй, ты, с той стороны» — и никто бы не отозвался.

**Диспетчер такси.** У машины есть номер, и в приложении видно: «Водитель Иван, номер 4521». Когда что-то идёт не так, вы говорите в поддержку именно «4521», а не «какой-то там водитель». Номер — единственный способ опознать нужную машину в потоке других.

**Очерёдность и приоритет в больнице.** Есть приоритет: экстренные случаи, срочные, плановые. Но приоритет — это не гарантия. Врач скорой может приехать к «срочному», а не к «экстренному», если скорых на всех не хватает. Приоритет — это просьба быть первым, а не приказ.

**Потоки в Java.** У потока есть **имя** — как позывной, — по которому вы отличаете его в логах и в дампах. И есть **приоритет** — как разряд в больнице, — который в теории должен влиять на порядок, но на практике влияет слабо. А ещё есть `currentThread()` — способ узнать, «кто я сейчас», из любого места кода.

Именно об этих трёх вещах — имя, приоритет и `currentThread()` — и пойдёт речь. Вещи простые, но без них отладка многопоточной программы превращается в поиск иголки в стоге сена, где все иголки выглядят одинаково.

## Теория

### Имя потока

У каждого потока есть имя. По умолчанию JVM даёт имена автоматически: `Thread-0`, `Thread-1`, `Thread-2` и так далее. Имя главного потока — `main`.

Увидеть имя можно через `getName()`:

```java
Thread thread = new Thread(() -> {});
System.out.println(thread.getName()); // Thread-0
```

Задать своё имя можно двумя способами.

**Через конструктор:**

```java
Thread thread = new Thread(() -> {}, "worker-1");
System.out.println(thread.getName()); // worker-1
```

**Через `setName()`:**

```java
Thread thread = new Thread(() -> {});
thread.setName("worker-1");
```

Переименовать можно и работающий поток — `setName()` не запрещает это делать. Но если переименовывать поток уже после запуска, в логах может возникнуть путаница: часть записей будет со старым именем, часть с новым. Поэтому имя лучше задавать при создании.

### Зачем давать потокам имена

Причин две, обе практические.

**Первая: отладка.** Когда программа падает или зависает, вы снимаете thread dump — снимок всех потоков с их состояними. В дампе видно:

```text
"Thread-3" #12 prio=5 os_prio=0 tid=0x... nid=0x... waiting on condition
"Thread-4" #13 prio=5 os_prio=0 tid=0x... nid=0x... waiting on condition
"Thread-5" #14 prio=5 os_prio=0 tid=0x... nid=0x... waiting on condition
```

Все три висят в `waiting`. А кто из них что делает? Непонятно. Теперь сравните:

```text
"http-worker-3" #12 prio=5 ... waiting on condition
"db-connection-1" #13 prio=5 ... waiting on condition
"cache-refresher" #14 prio=5 ... waiting on condition
```

Сразу видно: HTTP-воркер, соединение с базой, обновление кеша. Дальше можно догадаться, кто с кем не поделил ресурс.

**Вторая: логи.** В многопоточной программе записи в лог идут вперемешку. Если каждая строка начинается с имени потока — вы видите, какой поток что делал.

```text
[http-worker-1] Принят запрос от клиента
[http-worker-2] Принят запрос от клиента
[cache-refresher] Начинаю обновление кеша
[http-worker-1] Запрос обработан
```

Без имён все строки выглядели бы как одна сплошная каша, и разобрать, где чей запрос, было бы почти невозможно.

<div style="background-color: #1E0F33; border-left: 4px solid #B388FF; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #B388FF;">Правило:</strong> всегда давайте потокам осмысленные имена. Поток — это не анонимный исполнитель, а конкретный работник. У работника должно быть имя, по которому его видно в отчёте.
</div>

### Приоритет потока

У потока есть числовой приоритет — от 1 до 10. Есть три константы для удобства:

- `Thread.MIN_PRIORITY` = 1
- `Thread.NORM_PRIORITY` = 5
- `Thread.MAX_PRIORITY` = 10

По умолчанию у потока приоритет 5. Новый поток наследует приоритет того, кто его создал, — так что если вы создаёте поток из `main` с приоритетом 10, новый поток тоже получит 10.

Менять приоритет можно через `setPriority()`:

```java
Thread important = new Thread(() -> {}, "important");
important.setPriority(Thread.MAX_PRIORITY); // 10

Thread background = new Thread(() -> {}, "background");
background.setPriority(Thread.MIN_PRIORITY); // 1
```

И вот тут самое важное.

### Почему приоритетам нельзя доверять

Приоритет — это **подсказка планировщику**, а не команда. И подсказку эту планировщик может проигнорировать. Причины — три.

**Первая: реализация зависит от операционной системы.** В Java приоритеты потоков отображаются на приоритеты ОС, но не везде одинаково. На Linux с современными планировщиками (CFS) приоритеты потоков Java практически не учитываются — планировщик балансирует нагрузку по своим правилам. На Windows и на некоторых версиях macOS влияние сильнее, но всё равно не гарантировано.

**Вторая: планировщик может поступить по-своему.** Даже если ОС поддерживает приоритеты, планировщик может временно «поднять» низкоприоритетный поток, чтобы избежать голодания. То есть приоритет — это «пожелание», а не «жёсткое правило».

**Третья: JVM может вмешаться.** Некоторые реализации JVM игнорируют приоритеты полностью. И вы об этом даже не узнаете — просто однажды заметите, что программа ведёт себя не так, как вы рассчитывали.

В итоге:

```java
Thread high = new Thread(() -> System.out.println("high"), "high");
Thread low = new Thread(() -> System.out.println("low"), "low");
high.setPriority(Thread.MAX_PRIORITY);
low.setPriority(Thread.MIN_PRIORITY);
high.start();
low.start();
```

**Возможный вывод — и он же самый частый:**

```text
low
high
```

Или наоборот. Или вперемешку. **Приоритет не гарантирует порядок.** Он может его слегка подтолкнуть — а может и не подтолкнуть вовсе. Никогда не полагайтесь на приоритет для логики программы.

<div style="background-color: #251445; border-left: 4px solid #00E5D1; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #00E5D1;">Важно:</strong> приоритет — это <em>пожелание</em>, а не приказ. Если вам нужно, чтобы один поток завершился раньше другого — используйте <code>join()</code>, <code>wait()</code> или другие средства синхронизации. Приоритет для этого не подходит.
</div>

### Где приоритеты всё-таки полезны

Совсем без них не обходится. В некоторых сценариях приоритет может дать **небольшое** преимущество.

- **Фоновая задача, которая не должна мешать.** Вы можете дать потоку, качающему обновления, приоритет `MIN_PRIORITY` — не столько чтобы он реально уступал, сколько чтобы показать намерение. Иногда ОС отреагирует.
- **Задача, которую хочется выполнить быстрее остальных.** Тот же принцип: `MAX_PRIORITY` даёт чуть больше шансов, но не гарантию.
- **Совместимость с чужим кодом.** Если библиотека, которую вы используете, ожидает определённых приоритетов — стоит их выставить, даже если сами по себе они мало что дают.

Но в любом случае — **не полагайтесь на приоритет как на средство синхронизации**. Это инструмент «тонкой настройки», а не «управления».

### currentThread() — кто я сейчас

`Thread.currentThread()` — статический метод, который возвращает объект текущего потока. Того потока, который выполняет этот код прямо сейчас.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Мы в потоке: " + Thread.currentThread().getName());
        System.out.println("Приоритет: " + Thread.currentThread().getPriority());
    }
}
```

**Вывод:**

```text
Мы в потоке: main
Приоритет: 5
```

Это самый частый способ узнать, кто ты. Если вы пишете утилиту логирования, в которой каждая строка должна содержать имя потока, — `Thread.currentThread().getName()` ваш главный инструмент.

`currentThread()` возвращает именно тот объект, который выполняется в эту миллисекунду. Не «главный поток», не «поток, из которого меня вызвали», а **я сам**. Если вы внутри `Runnable.run()`, который выполняется в потоке `worker-1`, — `currentThread()` вернёт именно этот поток, а не `main`.

### Аналогия про позывной и разряд

Вернёмся к рации и больнице. Имя потока — это позывной. По нему вас узнают в эфире, по нему вас видно в отчёте. Без позывного вас не найдут.

Приоритет — это разряд в больнице. Он даёт вам **шанс** быть принятым раньше, но не гарантирует. Если врачей мало, а пациентов много — разряд поможет, а если сильно не повезёт — и он не спасёт. Разумный человек не полагается на разряд как на обещание, а разумный программист не полагается на приоритет как на синхронизацию.

`currentThread()` — это зеркало. Вы смотрите в него и видите, кто вы сейчас. Полезно, когда нужно понять, в каком потоке вы находитесь.

## Микрозадача 1: имя потока

**Задача:** Создайте поток с именем `worker-1`, который печатает своё имя три раза. Убедитесь, что в выводе фигурирует именно это имя, а не `Thread-0`.

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            for (int i = 0; i < 3; i++) {
                System.out.println("Я в потоке: " + Thread.currentThread().getName());
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
        }, "worker-1");

        worker.start();
        worker.join();
    }
}
```

**Вывод:**

```text
Я в потоке: worker-1
Я в потоке: worker-1
Я в потоке: worker-1
```

**Разбор:** имя задано в конструкторе — вторым аргументом. Внутри `run()` мы используем `Thread.currentThread().getName()`, а не `getName()` (у лямбды нет доступа к `getName()` — она не наследует `Thread`). Если бы имя не задали, вывод был бы `Thread-0`. Имя важно: в реальной отладке именно по нему вы будете отличать один поток от другого в логах и дампах.

## Микрозадача 2: приоритет не гарантирует порядок

**Задача:** Создайте два потока с именами `high` и `low`. Первому выставьте `MAX_PRIORITY`, второму — `MIN_PRIORITY`. Запустите несколько раз и убедитесь, что порядок вывода не гарантирован.

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        for (int attempt = 1; attempt <= 5; attempt++) {
            Thread high = new Thread(() -> System.out.print("high "), "high");
            Thread low = new Thread(() -> System.out.print("low "), "low");
            high.setPriority(Thread.MAX_PRIORITY);
            low.setPriority(Thread.MIN_PRIORITY);
            high.start();
            low.start();
            high.join();
            low.join();
            System.out.println(" (попытка " + attempt + ")");
        }
    }
}
```

**Возможный вывод:**

```text
high low  (попытка 1)
low high  (попытка 2)
high low  (попытка 3)
low high  (попытка 4)
high low  (попытка 5)
```

**Разбор:** порядок может быть любым, и не факт, что `high` окажется первым. Приоритет — подсказка, а не приказ. В некоторых запусках `low` действительно напечатается первым, потому что планировщик решил иначе. Именно поэтому нельзя строить логику программы на приоритетах: однажды всё сломается, и вы будете долго искать причину.

## 🎯 Самостоятельная задача

Напишите программу, которая:

1. Создаёт три потока с именами `reader-1`, `reader-2`, `reader-3`.
2. Каждый поток в цикле из десяти итераций печатает строку вида `[имя] итерация N` с паузой в 50 мс.
3. Поток `reader-1` получает приоритет `MAX_PRIORITY`, `reader-3` — `MIN_PRIORITY`, `reader-2` — по умолчанию.
4. Главный поток дожидается завершения всех трёх через `join()`.

Запустите программу несколько раз и посмотрите, влияет ли приоритет на порядок вывода. В комментарии к коду ответьте:

1. Заметили ли вы систематическую разницу в порядке выполнения `reader-1` и `reader-3`?
2. Если разница есть — она стабильная или случайная?
3. Почему на разных машинах результат может отличаться?
