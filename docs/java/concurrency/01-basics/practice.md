# Практикум по модулю 1. Основы потоков

## Зачем это

Мы прошли восемь глав. В каждой были микрозадачи и одна самостоятельная. Микрозадачи вы решали вместе со мной, самостоятельные — сами. Пора собрать всё, что вы узнали, в одном месте и проверить, работает ли это вместе.

Задачи этого практикума **сложнее** тех, что были в уроках. Не потому, что они требуют чего-то нового, а потому что требуют **комбинировать** материал нескольких глав. Если задача кажется неподъёмной — вернитесь к соответствующим главам, перечитайте, попробуйте ещё раз.

Решать лучше по одной в день, а не все за один вечер. Многопоточность — это навык, а не набор фактов. Он впитывается через практику и повторение.

**Разборы** всех задач — на отдельной странице: **[Разборы практикума](/java/concurrency/01-basics/practice-solutions)**. Сначала попробуйте сами, потом сверьтесь. Иначе не будет толку: вы прочитаете разбор, кивнёте — и через неделю не вспомните.

## Задача 1. Два счётчика

**Что комбинируется:** 1.2 (Thread vs Runnable), 1.7 (имена).

Напишите программу с двумя потоками через `Runnable`:

- Поток `even` печатает чётные числа от 0 до 20.
- Поток `odd` печатает нечётные числа от 1 до 19.

После каждого числа — пауза в 100 миллисекунд. Главный поток дожидается завершения обоих через `join()` и печатает «Готово».

**Ожидаемое поведение:** числа в выводе перемешиваются, потому что два потока работают одновременно.

**Что важно проверить:** имена потоков в выводе соответствуют тому, кто что печатает — `even` печатает только чётные, `odd` — только нечётные. Если наоборот или вперемешку — где-то ошибка в передаче задачи.

## Задача 2. Найди три ошибки

**Что комбинируется:** 1.3 (start vs run), 1.5 (join), 1.8 (daemon).

Вам дан код. В нём **три ошибки**, из-за которых программа ведёт себя не так, как задумано. Найдите их, объясните и исправьте.

```java
public class Main {
    public static void main(String[] args) {
        Thread worker = new Thread(() -> {
            try {
                for (int i = 0; i < 5; i++) {
                    System.out.println("Работаю: " + i);
                    Thread.sleep(500);
                }
            } catch (InterruptedException e) {
                // ничего
            }
            System.out.println("Готово");
        }, "worker");

        worker.run();
        System.out.println("main завершается");
    }
}
```

**Задумано:** поток `worker` печатает числа от 0 до 4 раз в полсекунды, потом «Готово». Главный поток ждёт завершения `worker` и печатает «main завершается».

**Что происходит на самом деле:** программа печатает числа в главном потоке и завершается, ничего не дождавшись.

**Подсказка:** ошибки не в коде задачи, а в способе её запуска и ожидания. И ещё одна — в том, как обрабатывается исключение.

## Задача 3. Все шесть состояний

**Что комбинируется:** 1.4 (жизненный цикл), 1.6 (interrupt).

Напишите программу, которая последовательно демонстрирует все шесть состояний потока и печатает их в консоль:

```text
NEW — поток создан, но не запущен
RUNNABLE — поток запущен
TIMED_WAITING — поток спит
WAITING — поток ждёт сигнала
BLOCKED — поток ждёт монитор
TERMINATED — поток завершён
```

**Требования:**

- Для `NEW` достаточно вывести состояние сразу после `new Thread(...)`.
- Для `TIMED_WAITING` запустите поток, который спит, и снимите состояние из главного потока.
- Для `BLOCKED` нужны два потока, конкурирующих за один монитор — как в главе 1.4.
- Для `WAITING` поток должен вызвать `wait()` внутри `synchronized`-блока, а наблюдатель — снять состояние и разбудить его через `notify()`.
- Для `TERMINATED` дождитесь завершения потока через `join()` и снимите состояние.

**Проверка:** все шесть состояний должны появиться в выводе в правильном порядке, с пояснениями.

## Задача 7. Диагноз по симптому

**Что комбинируется:** 1.4 (жизненный цикл), 1.5 (join), 1.8 (daemon).

Вам даны три программы. Каждая **зависает** — то есть не завершается, хотя должна. Для каждой найдите причину и предложите исправление.

**Программа А:**

```java
public class A {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        worker.start();
        worker.join();
        worker.join();
    }
}
```

**Программа Б:**

```java
public class B {
    public static void main(String[] args) throws InterruptedException {
        Thread daemon = new Thread(() -> {
            while (true) {
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
        });
        daemon.setDaemon(true);
        daemon.start();

        Thread normal = new Thread(() -> {
            try {
                Thread.sleep(5000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        normal.start();
        normal.join();
        // ...
    }
}
```

**Программа В:**

```java
public class V {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                // намеренно ничего не делаем
            }
        });
        t.start();
        while (t.isAlive()) {
            // ждём, пока поток жив
        }
    }
}
```

**Подсказка:** программа А — не зависает, но и не завершается так, как вы ожидаете. Программа Б — завершается, но с неприятным сюрпризом. Программа В — действительно может зависнуть.

## Задача 8. Резюме в одном приложении

**Что комбинируется:** всё.

Напишите программу, которая демонстрирует **все** ключевые концепции модуля за один запуск. Программа должна:

1. Создать три `Runnable`-задачи с именами `task-A`, `task-B`, `task-C`. Каждая спит случайное время от 1 до 3 секунд, потом печатает `[имя] завершена`.
2. Запустить все три задачи в обычных потоках.
3. Запустить **демон-поток** `monitor`, который каждые 300 миллисекунд печатает, сколько задач ещё работает, и корректно завершается по прерыванию.
4. Дождаться завершения всех трёх задач через `join()`.
5. Прервать `monitor` и дождаться его завершения.
6. Вывести итог: сколько задач завершилось и за сколько миллисекунд.

**Что проверяется:** умение собрать все части модуля в одной программе — создание задач, запуск, имена, ожидание, прерывание, демон-поток.

## 🎯 Проектное задание. Менеджер фоновых задач

Это задание сложнее предыдущих. Оно не про конкретную технику, а про **дизайн**: как организовать программу, чтобы она была понятной и предсказуемой. Можете решать его несколько вечеров.

### Постановка

Напишите класс `TaskManager`, который:

1. Принимает список задач (`Runnable`) с именами.
2. Запускает каждую задачу в отдельном потоке.
3. Ведёт демон-поток `reporter`, который каждую секунду печатает состояние: `[reporter] активно N задач из M`.
4. В основном методе ждёт завершения всех задач через `join()`.
5. В конце печатает сводку: сколько задач завершилось, сколько было прервано (если были), сколько времени заняло всё.
6. Корректно завершает `reporter` (через `interrupt`), не полагаясь на то, что JVM его «прибьёт».

### Требования к задачам

Задачи должны быть «реалистичными»: каждая спит случайное время (1–5 секунд) и с вероятностью 20% «падает» — выбрасывает `RuntimeException`. Задача должна:

- Поймать исключение внутри себя, напечатать `[имя] упала: причина`, корректно завершиться.
- В `finally`-блоке напечатать `[имя] уборка выполнена`.

**Ключевое требование:** исключение в одной задаче **не должно** останавливать другие. Каждая задача сама отвечает за свои ошибки.

### Что проверить

1. Если одна задача упала — остальные продолжают работать.
2. `reporter` корректно перестаёт печатать, когда его прерывают.
3. Общее время выполнения примерно равно времени **самой долгой** задачи, а не сумме всех — потому что задачи работают параллельно.
4. Сводка в конце правильная: сколько задач завершилось успешно, сколько упало.

### Задание со звёздочкой

Подумайте над вопросами:

1. Почему `reporter` — демон, а задачи — обычные потоки?
2. Что случится, если одну из задач сделать демоном? Почему это плохая идея?
3. Как бы вы модифицировали `TaskManager`, если бы задач было сто вместо трёх? Создавать сто потоков — плохо или нормально?

Ответьте в комментарии к коду. Однозначно правильных ответов на последний вопрос нет — важно ваше рассуждение.
