# 1.8. Демон-потоки

## Где вы это уже видели

**Уборщица в торговом центре.** Она работает, пока магазин открыт. Моет полы, протирает витрины, выносит мусор. Но когда последний посетитель выходит и двери запираются, её работу никто не ждёт. Она может быть посреди коридора со шваброй в руках — свет выключат, и всё. Никто не скажет: «подождите, дайте ей домыть». Магазин закрыт, значит, и уборка закончена.

**Аварийное освещение.** Оно горит в подвале и на лестницах всё время, пока здание работает. Когда здание обесточивают на ночь, аварийное освещение гаснет вместе с ним — и никого это не смущает. Оно и не должно было пережить здание.

**Фоновая музыка в кафе.** Играет, пока посетители сидят. Закрылось кафе — музыка выключилась. Никто не требует, чтобы песня доиграла до конца. Это фон, а не представление.

**Потоки в Java.** До сих пор все наши потоки были как посетители: JVM не завершится, пока хотя бы один из них работает. Но есть особый род потоков — **демоны**. Это потоки-уборщицы. Они работают в фоне, а когда все обычные потоки завершились, JVM просто выключает их, не дожидаясь, пока они домоют пол. И это правильно: они и не должны были пережить программу.

## Теория

### Что такое демон-поток

**Демон-поток** — это поток, который **не мешает JVM завершиться**. Если все обычные (не-демон) потоки завершили работу, JVM прекращает выполнение, и все демоны убиваются на полпути.

Разница между обычным потоком и демоном — не в том, что они делают. Разница — в том, **учитываются ли они при решении «пора заканчивать»**.

```text
Обычный поток: пока я работаю — программа работает.
Демон-поток:  пока я работаю — программа работает, но если все обычные
              закончили, меня выключат, не спросив.
```

JVM завершается, когда **последний не-демон поток** завершил работу. В этот момент все демоны убиваются, и их `run()` может не дойти до конца. `finally`-блоки, между прочим, тоже **не гарантируется**, что выполнится. Это важно и об этом ниже.

### Как создать демон-поток

Создать демон-поток просто: `setDaemon(true)` до запуска.

```java
Thread daemon = new Thread(() -> {
    while (true) {
        System.out.println("Я работаю в фоне");
        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return;
        }
    }
});
daemon.setDaemon(true);
daemon.start();
```

Порядок важен: `setDaemon()` нужно вызвать **до** `start()`. Если поток уже запущен — получите `IllegalThreadStateException`.

```java
Thread t = new Thread(() -> {});
t.start();
t.setDaemon(true); // IllegalThreadStateException
```

Причина проста: статус «демон или нет» определяется при создании потока и не может быть изменён во время работы. Это не техническое ограничение, а осознанное решение языка: иначе программа вела бы себя непредсказуемо.

<div style="background-color: #1E0F33; border-left: 4px solid #B388FF; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #B388FF;">Правило:</strong> <code>setDaemon(true)</code> — только до <code>start()</code>. После запуска поток уже не переделать.
</div>

### Проверка статуса

Узнать, демон ли поток, можно через `isDaemon()`:

```java
Thread t = new Thread(() -> {});
System.out.println(t.isDaemon()); // false — по умолчанию
t.setDaemon(true);
System.out.println(t.isDaemon()); // true
```

### Демоны наследуют статус

Если вы создаёте поток **из другого потока**, новый поток наследует статус родителя. То есть если поток `A` — демон, и он создаёт поток `B`, то `B` тоже будет демоном, если явно не указано обратное.

```java
Thread daemonParent = new Thread(() -> {
    Thread child = new Thread(() -> System.out.println("Я — " + Thread.currentThread().isDaemon()));
    System.out.println("Родитель — " + Thread.currentThread().isDaemon());
    child.start();
    try { child.join(); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
});
daemonParent.setDaemon(true);
daemonParent.start();
```

**Вывод:**

```text
Родитель — true
Я — true
```

Главный поток `main` — **не демон**, поэтому потоки, созданные из `main`, по умолчанию тоже не демоны. Это ещё одна причина, почему до сих пор мы не замечали разницы: все наши потоки были обычными.

### Что НЕЛЬЗЯ делать в демоне

Есть вещи, которые в демоне делать не стоит. Совсем.

**Первое: полагаться на `finally`.** Если JVM убивает демон в середине работы, `finally` может не выполниться. Это значит, что «закрыть файл в `finally`», «откатить транзакцию в `finally`», «записать в лог в `finally`» — всё это может **не сработать**.

```java
Thread daemon = new Thread(() -> {
    try {
        // работа с файлом
    } finally {
        // закрытие файла — МОЖЕТ НЕ ВЫПОЛНИТЬСЯ
    }
});
```

**Второе: держать ресурсы, требующие корректного освобождения.** Соединения с базой, файловые дескрипторы, сетевые сокеты. Если демон держит соединение и его убивают посреди работы — соединение останется «висящим» на стороне сервера до истечения таймаута. Для сервера это не проблема, для клиента — утечка.

**Третье: выполнять критически важную работу.** «Записать результат в файл», «отправить отчёт по почте», «сохранить состояние» — всё это в демоне ненадёжно. Если JVM решит выйти, — не запишет.

<div style="background-color: #251445; border-left: 4px solid #00E5D1; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #00E5D1;">Важно:</strong> демон подходит для <em>фонового обслуживания</em>, а не для <em>полезной работы</em>. Если ваш поток делает что-то, что должно быть сделано целиком, — он не должен быть демоном.
</div>

### Где демоны реально нужны

Демоны — не экзотика. Самые частые применения:

- **Сборщик мусора и другие служебные потоки JVM.** Когда ваша программа завершается, эти потоки не должны мешать JVM выключаться. Поэтому они — демоны.
- **Фоновые задачи мониторинга.** Снять метрики, обновить локальный кеш, прочитать конфигурацию. Пока программа работает — задача полезна; когда программа закрылась — она уже не нужна.
- **Таймеры и периодические задачи.** Например, поток, который раз в минуту проверяет наличие обновлений. Если программа закрылась, проверка уже не нужна.
- **Обработка входящих сообщений в фоновом режиме.** Слушатель очереди, который разбирает сообщения, но не должен держать программу живой.

А вот где демоны **не подходят**:

- **Запись файлов на диск.** Файл может остаться незаписанным до конца. Классический пример — незавершённый лог-файл.
- **Работа с базой данных.** Транзакция может остаться открытой, изменения — неприменёнными.
- **Любая задача, которую пользователь ожидает дождаться.** Если вы запустили экспорт данных и ждёте файл — поток должен быть обычным, а не демоном.

### Аналогия с уборщицей и посетителями

Вернёмся к началу главы. Магазин закрывается, когда **последний посетитель** выходит. Уборщица — не посетитель. Она работает в фоне, но её мнение «я ещё не домыла» никого не интересует. Свет выключат, двери запрут, и уборщица выйдет вместе со всеми.

Хороший менеджер ставит уборщицу в фон именно потому, что её работа — **обслуживание**. Плохой менеджер заставляет уборщицу задерживать закрытие магазина, потому что она «ещё не закончила».

А ещё есть работа, которую нельзя отдавать уборщице. Например, **инкассацию**. Если магазин закрывается, а инкассатор не успел вывезти выручку, — это уже не «домою потом», а «деньги остались в кассе». Поэтому инкассатор — не демон. Программа должна подождать, пока он закончит.

## Микрозадача 1: демон не мешает завершению

**Задача:** Создайте демон-поток, который в цикле печатает сообщение раз в секунду. В главном потоке подождите две секунды и завершитесь. Убедитесь, что программа заканчивается, не дожидаясь завершения демона.

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread daemon = new Thread(() -> {
            int i = 0;
            while (true) {
                System.out.println("Демон работает: " + i++);
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
        }, "background");
        daemon.setDaemon(true);
        daemon.start();

        Thread.sleep(2000);
        System.out.println("main завершается");
    }
}
```

**Возможный вывод:**

```text
Демон работает: 0
Демон работает: 1
main завершается
```

**Разбор:** демон напечатал два сообщения, потом главный поток завершил работу. JVM увидела: все не-демоны закончили — и выключилась, не дожидаясь, пока демон напечатает третье сообщение. Обратите внимание: `while (true)` в демоне **не привёл к вечной программе**. Если бы поток был обычным, программа висела бы бесконечно, пока вы её не прервёте вручную.

## Микрозадача 2: демон убивают посреди работы

**Задача:** Покажите, что `finally` в демоне может не выполниться. Создайте демон, который в `try` печатает «Работаю», спит долго, а в `finally` печатает «Закрываю ресурсы». Завершите главный поток раньше, чем демон дойдёт до `finally`.

**Решение:**

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread daemon = new Thread(() -> {
            try {
                System.out.println("Работаю");
                Thread.sleep(5000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            } finally {
                System.out.println("Закрываю ресурсы");
            }
        });
        daemon.setDaemon(true);
        daemon.start();

        Thread.sleep(500);
        System.out.println("main завершается");
    }
}
```

**Возможный вывод:**

```text
Работаю
main завершается
```

**Разбор:** строки «Закрываю ресурсы» **нет**. JVM убила демон прямо посреди `sleep()`, и `finally` не выполнился. В обычном потоке `finally` сработал бы почти наверняка — JVM дождалась бы завершения работы потока. Но с демоном гарантий нет. Именно поэтому нельзя доверять демону закрытие файлов, соединений и любых других ресурсов. Он умрёт, когда решит JVM, — а не когда закончит работу.

## 🎯 Самостоятельная задача

Напишите программу из трёх потоков:

1. **`worker`** — обычный поток, работает две секунды и печатает «worker: работа завершена».
2. **`monitor`** — демон-поток, каждую секунду печатает `monitor: тик N`.
3. **`cleanup`** — демон-поток с `try/finally`, в `try` спит пять секунд, в `finally` печатает `cleanup: ресурсы освобождены`.

Запустите все три. Дождитесь завершения только `worker` через `join()`.

В комментарии к коду ответьте:

1. Какие строки появятся в выводе, а какие — нет? Почему?
2. Что произойдёт, если сделать `cleanup` обычным потоком вместо демона?
3. В каком случае `cleanup` в реальной программе должен быть обычным потоком, а в каком — демоном?
