# 1.2. Создание потока: Thread vs Runnable

## Где вы это уже видели

В прошлой главе мы разобрали, зачем нужны потоки. Теперь другой вопрос: как именно сказать программе «выполни вот эту работу в отдельном потоке»?

Жизненных ситуаций, где это нужно, сколько угодно.

- **Загрузка файла.** Пользователь нажал «Скачать», а вы не хотите, чтобы интерфейс замёрз на минуту. Значит, загрузку нужно оформить как отдельную задачу и отдать потоку.
- **Сервер.** Пришёл запрос — его надо обработать в своём потоке, чтобы не задерживать остальные.
- **Анимация.** Пока вы считаете что-то тяжёлое, картинка должна продолжать перерисовываться в своём потоке.

Во всех этих случаях есть **задача** — то, что нужно сделать. И есть **исполнитель** — поток, который её делает. Главный вопрос главы: как правильно оформить задачу и как передать её исполнителю.

## Теория

### Два способа создать поток

В Java есть два канонических способа запустить свой поток.

1. **Унаследоваться от класса `Thread`** и переопределить метод `run()`.
2. **Реализовать интерфейс `Runnable`** и передать его в конструктор `Thread`.

Оба способа рабочие. Но один из них считается правильным, а второй — устаревшим стилем, который остался в языке для обратной совместимости. Разберём оба, чтобы понять, почему так.

### Способ первый: наследование от Thread

Класс `Thread` — это обёртка над системным потоком. У него есть метод `run()`, в котором описано, что поток должен делать. По умолчанию он пустой. Значит, если хотите свою работу — переопределите.

```java
public class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Работаю в потоке: " + Thread.currentThread().getName());
    }
}
```

Запуск такого потока выглядит так:

```java
public class Main {
    public static void main(String[] args) {
        MyThread thread = new MyThread();
        thread.start();
    }
}
```

Здесь `MyThread` — это одновременно и **задача**, и **исполнитель**. Класс сам себе и работа, и поток. На первый взгляд удобно: создал объект — он же и поток. В реальности это переплетение двух ролей и создаёт проблемы, о которых ниже.

### Способ второй: реализация Runnable

`Runnable` — это интерфейс с единственным методом `run()`. Он описывает **задачу**, и только её. Никакого отношения к потоку, его жизненному циклу и системным ресурсам.

```java
public class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("Работаю в потоке: " + Thread.currentThread().getName());
    }
}
```

Чтобы эта задача выполнилась в отдельном потоке, её нужно передать исполнителю:

```java
public class Main {
    public static void main(String[] args) {
        Runnable task = new MyTask();
        Thread thread = new Thread(task);
        thread.start();
    }
}
```

Теперь роли разделены: `MyTask` — это **что делать**, а `Thread` — это **кто делает**. Задачу можно передать другому потоку, положить в очередь, отдать пулу потоков. Об этом — в модуле 4.

### Почему Runnable предпочтительнее

Причин несколько, и все они практические.

**Первая: Java не поддерживает множественное наследование классов.** Класс может наследоваться только от одного родителя. Если ваш класс унаследован от `Thread`, то от чего-то другого, что вам нужно по бизнес-логике, он унаследоваться уже не сможет. А интерфейсов можно реализовать сколько угодно. `Runnable` не занимает единственное «место родителя».

**Вторая: разделение задачи и механизма запуска.** Задача — это «посчитать сумму массива». Механизм — «в каком потоке это выполнить». Это разные вещи, и смешивать их в одном классе — плохая идея. Сегодня вы запускаете задачу в одном потоке, завтра — в пуле из десяти, послезавтра — асинхронно. Если задача прибита гвоздями к `Thread`, каждый раз придётся её переписывать. Если это `Runnable` — она просто передаётся другому исполнителю.

**Третья: переиспользование.** Один и тот же `Runnable` можно запустить несколько раз в разных потоках, положить в очередь, передать в `ExecutorService`. С наследником `Thread` так не получится: объект `Thread` — одноразовый, повторный запуск того же объекта бросит исключение. Об этом — в следующей главе.

**Четвёртая: `Thread` сам реализует `Runnable`.** Это значит, что любой `Thread` можно передать туда, где ожидается `Runnable`. Обратное неверно. Выбирая `Runnable`, вы получаете более гибкий тип.

### Лямбда-выражения: короткая форма Runnable

`Runnable` — функциональный интерфейс, у него один абстрактный метод. Значит, вместо анонимного класса можно написать лямбду:

```java
public class Main {
    public static void main(String[] args) {
        Runnable task = () -> System.out.println("Работаю в потоке: " + Thread.currentThread().getName());
        new Thread(task).start();
    }
}
```

Или ещё короче, без промежуточной переменной:

```java
new Thread(() -> System.out.println("Работаю")).start();
```

Для коротких задач это самый читаемый вариант. Если логика большая — лучше вынести её в отдельный класс или метод, иначе `main` превратится в кашу.

### Что происходит при запуске

Метод `start()` — это не «вызвать `run()`». Это команда JVM: создай новый системный поток и начни выполнять в нём метод `run()`. Разница между `start()` и `run()` настолько важна, что ей посвящена целая следующая глава. Пока просто запомните: **запускаем поток через `start()`, а не через `run()`**.

### Итог: что выбрать

- **Задача** — почти всегда `Runnable`, часто в виде лямбды.
- **Наследование от `Thread`** — только если вам действительно нужно расширить поведение самого потока, а не описать работу. На практике это нужно крайне редко.

## Микрозадача 1: поток через наследование

**Задача:** Создайте класс, унаследованный от `Thread`, который печатает «Привет из потока» три раза. Запустите его из `main`.

**Решение:**

```java
public class GreetingThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 3; i++) {
            System.out.println("Привет из потока " + getName());
        }
    }

    public static void main(String[] args) {
        GreetingThread thread = new GreetingThread();
        thread.start();
    }
}
```

**Разбор:** внутри `run()` мы вызываем `getName()` без `Thread.currentThread()` — потому что `this` и есть поток, унаследованный от `Thread`, а `getName()` унаследован. Удобно? Да. Но именно эта «удобность» и есть ловушка: класс `GreetingThread` теперь навсегда привязан к `Thread`. Если завтра эту же задачу захочется выполнить в пуле потоков — придётся переписывать.

## Микрозадача 2: та же задача через Runnable

**Задача:** Сделайте то же самое, но через `Runnable`. Сравните объём кода и гибкость.

**Решение:**

```java
public class GreetingTask implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 3; i++) {
            System.out.println("Привет из потока " + Thread.currentThread().getName());
        }
    }

    public static void main(String[] args) {
        Thread thread = new Thread(new GreetingTask());
        thread.start();
    }
}
```

**Разбор:** в `run()` теперь нужно явно писать `Thread.currentThread().getName()`, потому что `GreetingTask` — не поток, у него нет своего имени. Зато `GreetingTask` — обычный класс, который можно передать куда угодно: в `Thread`, в пул потоков, в очередь. Одна и та же задача — разные способы исполнения.

## 🎯 Самостоятельная задача

Напишите программу с двумя потоками. Один печатает чётные числа от 0 до 20, другой — нечётные от 1 до 19. Каждый поток перед завершением выводит «Поток X закончил».

Оформите задачи через `Runnable`, а не через наследование от `Thread`. В комментарии к коду ответьте: почему вы выбрали `Runnable`, и что пришлось бы изменить в программе, если бы задачи нужно было выполнять не в отдельных потоках, а последовательно.
