# 3.1. CountDownLatch

## Где вы это уже видели

**Сбор группы в аэропорту.** Семеро друзей летят вместе. Договорились встретиться у стойки регистрации. Каждый добирается сам, своим маршрутом. Кто-то приехал раньше и сидит с чемоданом. Кто-то застрял в пробке. Все понимают: пока не придут **все семеро**, никто никуда не идёт. Стойка регистрации закрывается в 10:00, но вы ждёте именно людей, а не времени.

**Старт на соревнованиях.** Восемь спортсменов на беговой дорожке. Судья ждёт, пока все выйдут на старт. Каждый готовится сам, но **выстрел** раздаётся только когда готовы все. Нельзя, чтобы кто-то стартовал в одиночестве.

**Фильм в кинотеатре.** Все места в зале заняты? Нет, ещё двое опаздывают. Киномеханик не запускает фильм, пока не соберутся все зрители, которые забронировали места через приложение. Пока хоть один не пришёл — сеанс не начинается.

**Микросервисная система.** Сервис `order` не может начать принимать заказы, пока не подняты три зависимости: база данных, кеш, очередь сообщений. Каждая зависимость стартует со своей скоростью. `order` ждёт, пока **все три** будут готовы.

**Общее во всех случаях** одно: есть группа задач, которые стартуют независимо, и есть **точка сбора**, после которой начинается что-то общее. Ждать нужно именно **всех**, а не первого. Это и есть `CountDownLatch` — «защёлка обратного отсчёта».

## Теория

### Что такое CountDownLatch

`CountDownLatch` — примитив синхронизации из пакета `java.util.concurrent`. Он работает как **счётчик с защёлкой**:

- Создаётся с начальным значением `N`.
- Каждый поток, выполнивший свою работу, вызывает `countDown()` — уменьшает счётчик на 1.
- Потоки, которым нужно **дождаться**, вызывают `await()` — блокируются, пока счётчик не достигнет нуля.
- Когда счётчик достигает нуля, **все** ожидающие потоки просыпаются и продолжают работу.

Это одноразовый механизм. Один раз «дошёл до нуля» — и всё, защёлка открыта навсегда. Если нужен счётчик, который можно сбросить, — это `CyclicBarrier` (следующая глава).

### Простая схема

Представьте, что у вас есть задача, которая должна дождаться трёх других.

```java
import java.util.concurrent.CountDownLatch;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(3);

        for (int i = 1; i <= 3; i++) {
            int id = i;
            new Thread(() -> {
                try {
                    System.out.println("Задача " + id + " начала работу");
                    Thread.sleep(1000 * id); // разное время
                    System.out.println("Задача " + id + " завершена");
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    latch.countDown();
                }
            }, "worker-" + id).start();
        }

        System.out.println("main ждёт всех");
        latch.await();
        System.out.println("Все задачи завершены, main продолжает");
    }
}
```

**Возможный вывод:**

```text
main ждёт всех
Задача 1 начала работу
Задача 2 начала работу
Задача 3 начала работу
Задача 1 завершена
Задача 2 завершена
Задача 3 завершена
Все задачи завершены, main продолжает
```

Порядок завершения зависит от `sleep` — задачи 1, 2, 3 спят 1, 2, 3 секунды соответственно. `main` ждёт всех и печатает финальную строку только после последней.

### Ключевая идея: счётчик, а не флаг

`CountDownLatch` — это именно **счётчик**, а не флаг «готово/не готово». Это значит:

- Можно дождаться **N** событий, а не одного.
- Каждое событие — это `countDown()`. Счётчик уменьшается на 1.
- Никакого `notify()` вызывать не нужно — `countDown()` сам разбудит ждущих, когда счётчик дойдёт до нуля.

Это гораздо проще, чем `wait`/`notify`. Не нужно проверять условие в `while`, не нужно выбирать `notify` vs `notifyAll`. Просто «уменьшить на 1» и «дождаться нуля».

### Два способа использования

`CountDownLatch` используется в двух ролях, и их полезно различать.

#### Роль 1: «Стартовый пистолет»

Один поток ждёт, **N других** потоков делают `countDown()`. Классический пример — «дождаться, пока все воркеры завершат работу».

```java
CountDownLatch latch = new CountDownLatch(N);
// ... запускаем N потоков, каждый в конце: latch.countDown();
latch.await(); // ждём всех
```

Именно это мы сделали в примере выше.

#### Роль 2: «Стартовая линия»

**N потоков** ждут одного сигнала от **одного** потока. Классический пример — «все готовы, начинаем одновременно».

```java
CountDownLatch startSignal = new CountDownLatch(1);

for (int i = 0; i < N; i++) {
    new Thread(() -> {
        try {
            startSignal.await(); // все ждут сигнала
            // ... работа
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }).start();
}

// готовим всё, потом даём сигнал
startSignal.countDown();
```

Здесь счётчик 1: как только главный поток делает `countDown()`, все N ждущих просыпаются одновременно.

Можно совместить обе роли. Классический пример — «замер производительности»: N потоков ждут стартового сигнала, одновременно начинают, потом главный поток ждёт, пока все закончат.

```java
CountDownLatch start = new CountDownLatch(1);
CountDownLatch done = new CountDownLatch(N);

for (int i = 0; i < N; i++) {
    new Thread(() -> {
        try {
            start.await();
            // ... работа
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            done.countDown();
        }
    }).start();
}

long begin = System.nanoTime();
start.countDown(); // все стартуют одновременно
done.await();      // ждём всех
long elapsed = System.nanoTime() - begin;
System.out.println("Все N потоков отработали за " + elapsed / 1_000_000 + " мс");
```

Это стандартный паттерн в бенчмарках: «все стартуют одновременно, замеряем суммарное время». Без `start` потоки начали бы работу по мере создания, и замер был бы неточным.

### Методы

У `CountDownLatch` всего несколько методов.

**`CountDownLatch(int count)`** — конструктор, задаёт начальное значение.

**`void countDown()`** — уменьшить счётчик на 1. Если после уменьшения счётчик равен нулю — разбудить всех, кто ждёт. Если счётчик уже 0 — **ничего не делает** (не уходит в минус, не бросает исключение).

**`void await()`** — блокироваться, пока счётчик не станет 0. Если счётчик уже 0 — возвращается сразу.

**`boolean await(long timeout, TimeUnit unit)`** — блокироваться **не дольше** указанного времени. Возвращает `true`, если дождались, и `false`, если таймаут истёк. Это удобно, когда не хочется зависнуть навсегда из-за бага в чужом коде.

**`long getCount()`** — сколько ещё осталось. Полезно для отладки и логирования, не для синхронизации.

### CountDownLatch не сбрасывается

Это одноразовый примитив. После того как счётчик достиг нуля, `CountDownLatch` остаётся в этом состоянии навсегда. Повторно использовать его нельзя — `countDown()` больше ничего не делает, `await()` возвращается сразу.

Если вам нужен примитив, который можно переиспользовать, — это `CyclicBarrier` (глава 3.2) или `Phaser` (глава 3.4).

### CountDownLatch не заменяет synchronized

`CountDownLatch` — это механизм **координации**, а не **защиты данных**. Он не защищает от гонок. Он только позволяет одним потокам дождаться других.

Если у вас общие данные, к которым обращаются несколько потоков, — `CountDownLatch` их не защитит. Нужен `synchronized` или другой механизм из модуля 2.

### Частые ошибки

**Ошибка 1: неправильное начальное значение.** Если `CountDownLatch(3)`, а `countDown()` вызовут только дважды — `await()` будет ждать вечно. Третье событие никогда не произойдёт.

**Ошибка 2: забыть `countDown()` в `finally`.** Если поток упадёт с исключением до `countDown()` — счётчик не уменьшится, и `await()` будет ждать вечно. Всегда вызывайте `countDown()` в `finally`.

```java
try {
    // работа
} finally {
    latch.countDown(); // выполнится даже при исключении
}
```

**Ошибка 3: ждать больше, чем вызвано.** Если создали `CountDownLatch(5)`, а потоков, которые должны вызвать `countDown()`, только четыре — `await()` будет ждать вечно. Следите, чтобы `N` совпадало с реальным количеством событий.

**Ошибка 4: пытаться переиспользовать.** После того как счётчик дошёл до нуля, `CountDownLatch` больше не работает как «обратный отсчёт». Если нужен переиспользуемый механизм — `CyclicBarrier`.

**Ошибка 5: не использовать таймаут в проде.** `await()` без таймаута может ждать вечно, если что-то пошло не так. В продакшене обычно используют `await(timeout)`, чтобы не зависать.

### CountDownLatch vs join()

Может возникнуть вопрос: «А зачем `CountDownLatch`, если есть `Thread.join()`?» Ведь `join()` тоже ждёт завершения потоков.

Разница вот в чём.

`join()` ждёт **завершения потока**. Поток должен закончить `run()`, чтобы `join()` вернулся.

`CountDownLatch` ждёт **сигнала**. Поток может продолжать работать после `countDown()` — это не «завершение», а «событие».

Это важно. Например, сервис может сигнализировать «я готов принимать трафик» и продолжать работать (обрабатывать запросы). `join()` тут не подойдёт — поток не завершится, пока сервис работает. А `CountDownLatch` — подойдёт: `countDown()` вызывается в момент готовности, `await()` ждёт этой готовности, а поток продолжает обрабатывать запросы.

Кроме того, `CountDownLatch` позволяет ждать **события**, а не потоки. Событие может произойти в одном потоке, но означать готовность чего-то большего. `join()` привязан к потокам, а `CountDownLatch` — к событиям.

### Аналогия с аэропортом

Вернёмся к началу. `CountDownLatch` — это **стойка регистрации**, где встречаются семеро друзей. Каждый, кто пришёл, «отмечается» (`countDown`). Кто ещё не пришёл — не отмечается. Когда пришли все семеро — защёлка открывается, все идут на посадку.

`join()` — это если бы вы ждали **каждого** персонально, стоя у выхода с табличкой «Иван, Петров, Сидоров…». Пришёл Иван — ждёте Петрова. Пришёл Петров — ждёте Сидорова. Это работает, но неудобно, если друзей много или если вы не знаете, в каком порядке они придут.

`CountDownLatch` — это одна стойка, где каждый отмечается, и вы ждёте, пока счётчик дойдёт до нуля. Проще и надёжнее.

## Микрозадача 1: дождаться трёх задач

**Задача:** Создайте `CountDownLatch(3)` и три потока. Каждый поток спит случайное время от 1 до 3 секунд, потом печатает «задача N завершена» и вызывает `countDown()`. Главный поток ждёт `await()` и печатает «все задачи завершены» и общее время.

**Решение:**

```java
import java.util.concurrent.CountDownLatch;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(3);
        long start = System.currentTimeMillis();

        for (int i = 1; i <= 3; i++) {
            int id = i;
            new Thread(() -> {
                try {
                    long sleep = 1000 + (long) (Math.random() * 2000);
                    Thread.sleep(sleep);
                    System.out.println("Задача " + id + " завершена за " + sleep + " мс");
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    latch.countDown();
                }
            }, "worker-" + id).start();
        }

        latch.await();
        long elapsed = System.currentTimeMillis() - start;
        System.out.println("Все задачи завершены, общее время: " + elapsed + " мс");
    }
}
```

**Возможный вывод:**

```text
Задача 2 завершена за 1234 мс
Задача 1 завершена за 1890 мс
Задача 3 завершена за 2876 мс
Все задачи завершены, общее время: 2880 мс
```

**Разбор:** задачи работают параллельно, каждая спит своё время. Главный поток ждёт, пока счётчик не дойдёт до нуля, — то есть пока все три не вызовут `countDown()`. Общее время примерно равно времени **самой долгой** задачи, а не сумме. Если бы запускали последовательно — было бы около 6 секунд, а тут — около 3. `countDown()` в `finally` гарантирует, что даже при исключении счётчик уменьшится.

## Микрозадача 2: стартовый пистолет

**Задача:** Пять потоков должны начать работу **одновременно** по сигналу. Каждый поток печатает «готов», ждёт `await()` на общем `CountDownLatch(1)`, потом печатает «стартовал». Главный поток ждёт, пока все напечатают «готов», и делает `countDown()`.

**Решение:**

```java
import java.util.concurrent.CountDownLatch;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        int N = 5;
        CountDownLatch ready = new CountDownLatch(N);
        CountDownLatch start = new CountDownLatch(1);

        for (int i = 1; i <= N; i++) {
            int id = i;
            new Thread(() -> {
                try {
                    System.out.println("worker-" + id + ": готов");
                    ready.countDown();
                    start.await();
                    System.out.println("worker-" + id + ": стартовал");
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }, "worker-" + id).start();
        }

        ready.await(); // ждём, пока все будут готовы
        System.out.println("Все готовы. Старт!");
        start.countDown(); // даём сигнал
    }
}
```

**Возможный вывод:**

```text
worker-1: готов
worker-2: готов
worker-3: готов
worker-4: готов
worker-5: готов
Все готовы. Старт!
worker-2: стартовал
worker-4: стартовал
worker-1: стартовал
worker-5: стартовал
worker-3: стартовал
```

**Разбор:** здесь используются **два** `CountDownLatch` — классический паттерн. `ready` считает, сколько потоков готовы. `start` — это сигнал к старту. Главный поток ждёт `ready.await()`, потом делает `start.countDown()` — и все пять потоков просыпаются одновременно. Порядок «стартовал» в выводе случайный, потому что после `start.await()` все пять потоков конкурируют за процессор.

Этот паттерн часто используется в бенчмарках: сначала все потоки готовятся, потом одновременно стартуют — чтобы замер был честным.

## 🎯 Самостоятельная задача

Реализуйте **параллельный загрузчик**, который:

1. Принимает массив URL-адресов (можно фейковых, вместо реальной загрузки — `Thread.sleep`).
2. Создаёт `CountDownLatch` на количество URL.
3. Запускает по потоку на каждый URL. Каждый поток «загружает» файл (спит случайное время 500–2000 мс), пишет результат в общий массив, вызывает `countDown()`.
4. Главный поток ждёт `await()` и печатает, сколько файлов загружено, сколько было ошибок (если имитировать ошибки через `RuntimeException` в некоторых потоках), и общее время.

**Требования:**

- Используйте `CountDownLatch` и `finally` для `countDown()`.
- Результаты складывайте в массив **заранее известного размера** (по индексу), чтобы не было гонки.
- Если поток «упал» с исключением — всё равно вызовите `countDown()` и отметьте в результате, что это была ошибка.

**Дополнительно:** добавьте таймаут — `latch.await(10, TimeUnit.SECONDS)`. Если не все загрузки завершились за 10 секунд, выведите предупреждение и продолжайте.

## 📌 Что дальше

В следующей главе — **«CyclicBarrier»**. Это примитив, который решает похожую задачу, но с двумя отличиями: его можно переиспользовать, и он ждёт, пока **все** участники дойдут до точки сбора, а потом пропускает их **всех** дальше. `CountDownLatch` — это «дождаться N событий и пойти дальше», а `CyclicBarrier` — «все встретились, все идут дальше». Разница тонкая, но важная — и вы теперь готовы её понять.
