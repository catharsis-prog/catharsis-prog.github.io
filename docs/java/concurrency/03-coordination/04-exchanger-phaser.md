# 3.4. Exchanger и Phaser

## Где вы это уже видели

**Обмен книгами.** Двое договорились: один приносит книгу, другой — свою. Встречаются в кафе, обмениваются, расходятся. Пока второй не пришёл — первый сидит и ждёт. Когда оба на месте — обмен происходит мгновенно. Это `Exchanger`.

**Сдача проекта по этапам.** Команда работает над проектом: сначала планирование (все вместе), потом разработка (кто-то уходит в отпуск, кто-то подключается), потом тестирование (снова все вместе), потом релиз. Этапы сменяют друг друга, а состав команды на каждом этапе разный. Это `Phaser`.

**Эстафета.** Четыре бегуна. Первый бежит, передаёт эстафету второму, второй — третьему, третий — четвёртому. Пока палочка не передана — следующий не бежит. Обмен «палочкой» между двумя — это `Exchanger`. А вся эстафета целиком — это `Phaser` с фазами.

**Игра в паре.** Настольная игра на двоих. Один ходит, другой смотрит. Потом меняются ролями: тот, кто смотрел, — ходит. Обмен ролями — это `Exchanger`. А последовательность партий до победы одного из игроков — это `Phaser`.

**Общее во всех случаях** одно: есть **точка обмена** или **точка перехода**, где участники встречаются, что-то передают друг другу, и продолжают. Иногда участников ровно двое (`Exchanger`), иногда — сколько угодно, и они могут меняться (`Phaser`).

## Теория

### Exchanger: обмен между двумя

`Exchanger<T>` — простой примитив из `java.util.concurrent`. Он работает как **точка рандеву** для двух потоков: каждый приходит со своим значением, оба ждут друг друга, когда оба на месте — **обмениваются** значениями и расходятся.

```java
import java.util.concurrent.Exchanger;

public class Main {
    public static void main(String[] args) {
        Exchanger<String> exchanger = new Exchanger<>();

        Thread t1 = new Thread(() -> {
            try {
                String myValue = "от t1";
                System.out.println("t1 пришёл с: " + myValue);
                String received = exchanger.exchange(myValue);
                System.out.println("t1 получил: " + received);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "t1");

        Thread t2 = new Thread(() -> {
            try {
                String myValue = "от t2";
                System.out.println("t2 пришёл с: " + myValue);
                String received = exchanger.exchange(myValue);
                System.out.println("t2 получил: " + received);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "t2");

        t1.start();
        t2.start();
    }
}
```

**Возможный вывод:**

```text
t1 пришёл с: от t1
t2 пришёл с: от t2
t1 получил: от t2
t2 получил: от t1
```

Обратите внимание: **каждый получил то, что принёс другой**. `t1` отдал «от t1» и получил «от t2». `t2` — наоборот. Это и есть обмен.

### Как работает exchange()

`exchange(V value)` делает три вещи.

1. **Отдаёт** ваше значение.
2. **Блокируется**, пока не придёт другой поток со своим значением.
3. **Возвращает** значение, которое принёс другой поток.

Если второй поток уже ждёт — обмен происходит сразу. Если нет — вы ждёте. Один ждёт — другой ждёт — встреча — обмен — оба продолжают.

### Только два потока

Ключевое ограничение `Exchanger`: **он работает ровно с двумя потоками**. Не с тремя, не с четырьмя. Если три потока вызовут `exchange()` — один останется ждать навсегда (пока не придёт четвёртый).

Это не баг, а особенность дизайна. `Exchanger` — для парного обмена, и только. Если вам нужно обмениваться группой — используйте `BlockingQueue` (модуль 5) или `Phaser`.

### exchange() с таймаутом

Как и у других примитивов, у `Exchanger` есть версия с таймаутом:

```java
try {
    String received = exchanger.exchange(myValue, 1, TimeUnit.SECONDS);
} catch (TimeoutException e) {
    // никто не пришёл за секунду
}
```

Если второй поток не пришёл за указанное время — бросается `TimeoutException`. Это спасает от зависания, если партнёр по какой-то причине не появился.

### Типичное применение: pipeline из двух этапов

Классическое применение `Exchanger` — **двухэтапный конвейер**, где два потока обмениваются буферами.

Представьте: один поток читает данные из сети, другой — обрабатывает. Первый наполняет буфер, второй его опустошает. Когда буфер полон — они меняются: первый берёт пустой буфер, второй — полный.

```java
Exchanger<StringBuilder> exchanger = new Exchanger<>();

Thread producer = new Thread(() -> {
    StringBuilder buffer = new StringBuilder();
    try {
        while (true) {
            // наполняем буфер
            buffer.append("данные ");
            // обмениваемся с consumer
            buffer = exchanger.exchange(buffer);
            buffer.setLength(0); // очищаем полученный буфер
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
});

Thread consumer = new Thread(() -> {
    StringBuilder buffer = new StringBuilder();
    try {
        while (true) {
            // получаем наполненный буфер
            buffer = exchanger.exchange(buffer);
            // обрабатываем
            System.out.println("Получено: " + buffer);
            buffer.setLength(0);
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
});
```

Это паттерн **double buffering**: пока один поток наполняет буфер, другой обрабатывает предыдущий. Обмен происходит в одной точке, без блокировок и без копирования — потоки просто меняются объектами.

### Типичное применение: генетический алгоритм

В генетических алгоритмах есть **скрещивание** — две особи обмениваются частью генов и создают потомков. `Exchanger` идеально подходит:

```java
Exchanger<Individual> exchanger = new Exchanger<>();

// Поток 1
Individual mine = ...;
Individual partner = exchanger.exchange(mine);
Individual child = crossover(mine, partner);

// Поток 2
Individual mine = ...;
Individual partner = exchanger.exchange(mine);
Individual child = crossover(mine, partner);
```

Оба потока обмениваются «своими» особями, каждый создаёт потомка. Просто и элегантно.

### Phaser: многофазная координация

`Phaser` — примитив, который обобщает `CyclicBarrier` и `CountDownLatch`. Он позволяет:

- Работать с **фазами** (как `CyclicBarrier` с раундами).
- **Динамически** добавлять и удалять участников.
- Иметь **хук** на переход между фазами.
- Завершать работу, когда нужно.

`Phaser` — это как `CyclicBarrier`, у которого число участников может меняться между фазами.

### Простая схема

```java
import java.util.concurrent.Phaser;

public class Main {
    public static void main(String[] args) {
        int N = 3;
        Phaser phaser = new Phaser(N); // N участников

        for (int i = 1; i <= N; i++) {
            int id = i;
            new Thread(() -> {
                try {
                    System.out.println("worker-" + id + " фаза 0");
                    phaser.arriveAndAwaitAdvance();

                    System.out.println("worker-" + id + " фаза 1");
                    phaser.arriveAndAwaitAdvance();

                    System.out.println("worker-" + id + " фаза 2");
                    phaser.arriveAndDeregister(); // выходим из игры
                } catch (Exception e) {
                    Thread.currentThread().interrupt();
                }
            }, "worker-" + id).start();
        }
    }
}
```

**Возможный вывод:**

```text
worker-1 фаза 0
worker-2 фаза 0
worker-3 фаза 0
worker-1 фаза 1
worker-2 фаза 1
worker-3 фаза 1
worker-1 фаза 2
worker-2 фаза 2
worker-3 фаза 2
```

Каждая фаза начинается только когда все участники дошли до её конца. Как `CyclicBarrier`, но с возможностью **выйти** из игры через `arriveAndDeregister()`.

### Ключевые методы Phaser

**`arrive()`** — «я дошёл до точки сбора». Уменьшает счётчик прибывших. Не блокируется.

**`arriveAndAwaitAdvance()`** — «я дошёл и жду остальных». Уменьшает счётчик и блокируется, пока все не придут. Это аналог `barrier.await()` в `CyclicBarrier`.

**`arriveAndDeregister()`** — «я дошёл и выхожу из игры». Уменьшает счётчик и **уменьшает число участников** на 1. Поток больше не участвует в следующих фазах. Аналог «уволиться».

**`register()`** — «добавьте меня в игру». Увеличивает число участников на 1. Новый поток присоединяется к следующей фазе. Аналог «наняться».

**`bulkRegister(int parties)`** — добавить сразу несколько участников.

**`getPhase()`** — номер текущей фазы. Начинается с 0, растёт при каждой смене.

**`getRegisteredParties()`** — сколько сейчас зарегистрировано.

**`getArrivedParties()`** — сколько уже пришло в текущей фазе.

**`getUnarrivedParties()`** — сколько ещё не пришло.

**`isTerminated()`** — завершён ли фазер.

**`forceTermination()`** — принудительно завершить.

### Хук onAdvance

`Phaser` позволяет задать хук, который выполняется **при переходе между фазами**. Это аналог `BarrierAction` в `CyclicBarrier`, но с большими возможностями.

```java
Phaser phaser = new Phaser(N) {
    @Override
    protected boolean onAdvance(int phase, int registeredParties) {
        System.out.println("Завершена фаза " + phase + ", участников: " + registeredParties);
        return registeredParties == 0; // вернуть true — завершить
    }
};
```

`onAdvance` вызывается **после** того, как все участники пришли, но **до** того, как они продолжат. Он получает номер фазы и число зарегистрированных участников. Возвращает `boolean`: `true` — завершить фазер, `false` — продолжать.

Хук выполняется в потоке, который **последним** пришёл к точке сбора. Как и в `CyclicBarrier`, не гарантируется, что это всегда один и тот же поток.

Часто `onAdvance` используют для:

- Печати отчёта о фазе.
- Агрегации результатов.
- **Автоматического завершения** — когда все участники ушли (`registeredParties == 0`).

### Динамическое изменение участников

Главное отличие `Phaser` от `CyclicBarrier` — можно **добавлять и убирать** участников между фазами.

```java
Phaser phaser = new Phaser(1); // главный поток + те, кто присоединится

// главный поток регистрирует рабочих
for (int i = 0; i < N; i++) {
    phaser.register();
    new Thread(() -> {
        try {
            // работа в фазе
            phaser.arriveAndAwaitAdvance();
        } finally {
            phaser.arriveAndDeregister();
        }
    }).start();
}

// главный поток тоже участвует
phaser.arriveAndAwaitAdvance();
```

Здесь главный поток **регистрирует** рабочих (увеличивает число участников), а рабочие в конце **дерегистрируются** (уменьшают). Число участников меняется.

Это позволяет строить сложные сценарии: например, на первой фазе работают все, на второй — только половина (остальные ушли), на третьей — снова все (пришли новые).

### Автоматическое завершение

Если все участники ушли (`arriveAndDeregister`), `Phaser` автоматически завершается. По умолчанию `onAdvance` возвращает `registeredParties == 0`, то есть «завершить, когда никого не осталось».

Это удобно: не нужно явно вызывать `terminate()`. Просто все ушли — фазер закончил работу.

Но если у вас в `onAdvance` своя логика — убедитесь, что она возвращает `true` в нужный момент, иначе фазер может работать вечно.

### Phaser vs CyclicBarrier

`Phaser` и `CyclicBarrier` решают похожие задачи, но с разными акцентами.

| | CyclicBarrier | Phaser |
|---|---|---|
| Число участников | Фиксированное | Динамическое |
| Добавить участника | Нет | Да (`register`) |
| Убрать участника | Нет | Да (`arriveAndDeregister`) |
| Хук на переход | `BarrierAction` | `onAdvance` |
| Фазы | Сброс после сбора | Номера фаз |
| Завершение | Никогда (пока не выброшен) | Автоматическое, когда все ушли |
| Сложность | Проще | Гибче |

**Правило выбора.** Если у вас фиксированная группа и простые раунды — `CyclicBarrier`. Если число участников меняется или нужны сложные фазы — `Phaser`.

### Exchanger vs Phaser vs CyclicBarrier

Все три примитива из этой главы — про встречу. Но встречаются они по-разному.

- **`Exchanger`** — встреча **двух** потоков для **обмена значениями**. Встретились, обменялись, разошлись.
- **`CyclicBarrier`** — встреча **фиксированной группы** для **синхронизации фазы**. Все пришли, все пошли дальше.
- **`Phaser`** — встреча **переменной группы** для **синхронизации фазы**. Все пришли, все пошли дальше, кто-то может присоединиться или уйти.

### Аналогия с обменом книг и сдачей проекта

Вернёмся к началу. `Exchanger` — это **обмен книгами**: двое, каждый со своей, встречаются, обмениваются, расходятся. Если третий захочет тоже — он будет стоять и ждать пару, потому что `Exchanger` работает только с двумя.

`Phaser` — это **сдача проекта по этапам**: команда собирается на планирование, кто-то уходит в отпуск, кто-то подключается к разработке, все собираются на тестирование, кто-то уходит, оставшиеся выпускают релиз. Состав меняется, этапы сменяются, но координация есть на каждом этапе.

`CyclicBarrier` — это если бы состав был **фиксированным**: те же люди, те же этапы, без отпусков и подключений. Проще, но менее гибко.

## Микрозадача 1: обмен значениями

**Задача:** Создайте два потока, каждый приносит строку. Используйте `Exchanger`, чтобы они обменялись. Убедитесь, что каждый получил то, что принёс другой.

**Решение:**

```java
import java.util.concurrent.Exchanger;

public class Main {
    public static void main(String[] args) {
        Exchanger<String> exchanger = new Exchanger<>();

        Thread t1 = new Thread(() -> {
            try {
                String mine = "привет от t1";
                String received = exchanger.exchange(mine);
                System.out.println("t1 получил: " + received);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "t1");

        Thread t2 = new Thread(() -> {
            try {
                String mine = "привет от t2";
                String received = exchanger.exchange(mine);
                System.out.println("t2 получил: " + received);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, "t2");

        t1.start();
        t2.start();
    }
}
```

**Возможный вывод:**

```text
t1 получил: привет от t2
t2 получил: привет от t1
```

**Разбор:** каждый поток пришёл со своим значением, обменялся и получил чужое. `exchange()` блокируется, пока второй не придёт. Если один пришёл раньше — он ждёт. Порядок в выводе может быть любым: кто первым получил — зависит от планировщика.

## Микрозадача 2: простая фазовая координация

**Задача:** Создайте `Phaser(3)` и три потока. Каждый проходит три фазы, в каждой печатает `[имя] фаза N` и ждёт `arriveAndAwaitAdvance()`. После третьей фазы — `arriveAndDeregister()`. Убедитесь, что фазы синхронизированы.

**Решение:**

```java
import java.util.concurrent.Phaser;

public class Main {
    public static void main(String[] args) {
        Phaser phaser = new Phaser(3);

        for (int i = 1; i <= 3; i++) {
            int id = i;
            new Thread(() -> {
                try {
                    for (int phase = 0; phase < 3; phase++) {
                        System.out.println("[worker-" + id + "] фаза " + phase);
                        phaser.arriveAndAwaitAdvance();
                    }
                    phaser.arriveAndDeregister();
                } catch (Exception e) {
                    Thread.currentThread().interrupt();
                }
            }, "worker-" + id).start();
        }
    }
}
```

**Возможный вывод:**

```text
[worker-1] фаза 0
[worker-2] фаза 0
[worker-3] фаза 0
[worker-1] фаза 1
[worker-2] фаза 1
[worker-3] фаза 1
[worker-1] фаза 2
[worker-2] фаза 2
[worker-3] фаза 2
```

**Разбор:** фазы идут строго по порядку. Все три потока проходят фазу 0, потом все три — фазу 1, потом фазу 2. После третьей фазы каждый вызывает `arriveAndDeregister()` — выходит из игры. Когда все три вышли — `registeredParties == 0`, фазер автоматически завершается. Программа заканчивается без явного `terminate()`.

## 🎯 Самостоятельная задача

Реализуйте **двухэтапный конвейер обработки данных** с использованием `Exchanger` и `Phaser` вместе.

**Постановка:**

1. Есть **три** потока-обработчика. Каждый работает в цикле из пяти итераций.
2. На каждой итерации:
   - Поток генерирует «данные» (случайное число).
   - Через `Exchanger` обменивается с партнёром (потоки разбиты на пары: 1-2, 3 — ждёт, 4 — нет, у нас три потока... подумайте, как организовать обмен при нечётном числе).
   - Полученные данные «обрабатывает» (печатает).
3. Между итерациями все три потока синхронизируются через `Phaser` — чтобы итерации шли согласованно.
4. После пяти итераций все три потока завершаются.

**Требования:**

- Используйте `Exchanger` для обмена данными между двумя потоками.
- Используйте `Phaser` для синхронизации итераций между всеми тремя.
- Программа не должна зависать. Если третий поток остаётся без пары — он должен обработать свои данные сам (без обмена) и дождаться остальных на фазере.

**Дополнительно:** сделайте так, чтобы число потоков задавалось параметром. Если число чётное — все разбиваются на пары. Если нечётное — один работает без пары.

## 📌 Что дальше

В следующей главе — **«Lock и Condition»**. Это более гибкая альтернатива `synchronized`: явный захват и освобождение блокировки, `tryLock` с таймаутом, справедливость, множественные `Condition` для разных условий ожидания. А то ведь до сих пор мы использовали `synchronized`, у которого нет ни таймаута, ни справедливости, ни возможности прервать ожидание. Пора познакомиться с инструментом, у которого всё это есть.
