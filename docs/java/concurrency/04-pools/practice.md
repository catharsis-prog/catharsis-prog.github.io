## Задача 2. Найди три ошибки

**Что комбинируется:** 4.2, 4.3, 4.5.

Вам дан код. В нём **три ошибки**, из-за которых программа либо висит, либо теряет задачи, либо ведёт себя непредсказуемо. Найдите их, объясните и исправьте.

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(4);

        for (int i = 0; i < 1000; i++) {
            int id = i;
            pool.submit(() -> {
                if (id % 100 == 0) {
                    throw new RuntimeException("Задача " + id + " упала");
                }
                System.out.println("Задача " + id + " выполнена");
            });
        }

        pool.shutdown();
    }
}
```

**Подсказки:**

- Одна ошибка — в том, что `submit` возвращает `Future`, а мы его игнорируем. Если задача упала — исключение теряется.
- Вторая — в отсутствии `awaitTermination`. `shutdown()` не блокируется, а `main` сразу завершается.
- Третья — в том, что не закрыт доступ к `id` — но нет, это не ошибка (лямбда захватывает финальную копию). Третья ошибка — в том, что при исключении в задаче пул продолжает принимать задачи, но никто не считает упавшие, и в итоге мы не знаем, сколько выполнено.

## Задача 3. Планировщик с отменой

**Что комбинируется:** 4.4 (`ScheduledExecutorService`), 4.5 (shutdown), 2.4 (`volatile`).

Создайте систему из трёх периодических задач:

1. **`heartbeat`** — каждые 500 мс печатает «жив».
2. **`metrics`** — раз в 2 секунды печатает размер очереди задач (фиктивной, просто счётчик).
3. **`cleanup`** — раз в 5 секунд печатает «уборка».

Через 10 секунд после запуска **отмените** `cleanup` (через `ScheduledFuture.cancel`). Через 15 секунд отмените всё и корректно завершите пул.

**Требования:**

1. Все задачи должны иметь `try/catch(Throwable)` — чтобы `metrics`, если случайно упадёт, не умерла навсегда.
2. Отмена — через `cancel(false)`.
3. Завершение — `shutdown()` + `awaitTermination(5, TimeUnit.SECONDS)`. Если не завершилось — `shutdownNow()`.
4. После завершения напечатайте, сколько раз выполнилась каждая задача.

**Дополнительно:** сделайте `metrics` «падучей» — с вероятностью 20% бросает `RuntimeException`. Убедитесь, что она продолжает работать. Затем **уберите** `try/catch` и запустите снова — убедитесь, что после первого падения `metrics` тихо умирает, а `heartbeat` и `cleanup` продолжают работать.

## Задача 4. ForkJoinPool: параллельный WordCount

**Что комбинируется:** 4.6 (`ForkJoinPool`), 4.3 (`ThreadPoolExecutor` — для сравнения).

Реализуйте параллельный подсчёт слов в большом тексте.

**Постановка:**

1. «Текст» — массив из 10 миллионов слов (строк), сгенерированный случайно из 1000 разных слов.
2. Нужно посчитать, сколько раз встречается каждое слово.
3. Реализуйте через `RecursiveTask<Map<String, Integer>>`:
   - база рекурсии — кусок меньше `THRESHOLD` слов: считаем в `HashMap` и возвращаем.
   - рекурсия — делим на две половины, каждая возвращает `Map`, потом **сливаем** две мапы.
4. Замерьте время. Сравните с последовательным подсчётом.

**Требования:**

- Слияние мап — в `compute()`, после `join()`. Убедитесь, что слияние корректное (складываем значения).
- `THRESHOLD` попробуйте 1000, 10_000, 100_000. Замерьте. Какой оптимален?
- Проверьте: результаты параллельного и последовательного подсчёта совпадают.

**Дополнительно:** вместо слияния мап в каждой ноде попробуйте собрать все «сырые» куски в `ConcurrentHashMap` через `merge()`. Сравните производительность.

## Задача 6. Корректное завершение под нагрузкой

**Что комбинируется:** 4.5 (shutdown), 1.6 (прерывания), 1.8 (демоны).

Напишите систему, которая **должна** корректно завершиться при сигнале остановки.

**Постановка:**

1. `ThreadPoolExecutor(4, 8, 30s, ArrayBlockingQueue(10))`.
2. 100 задач, каждая спит 200 мс, в `try/catch` обрабатывает `InterruptedException` — логирует «прервана» и корректно возвращается.
3. Главный поток ждёт 1 секунду, потом вызывает `shutdown()`.
4. Ждёт `awaitTermination(3, TimeUnit.SECONDS)`. Если не дождался — `shutdownNow()`, потом ещё раз `awaitTermination(3, TimeUnit.SECONDS)`.
5. Соберите статистику: сколько задач завершилось, сколько было прервано, сколько не началось.

**Требования:**

- Каждая задача сама решает, что делать с прерыванием.
- Статистика — через `AtomicInteger`.
- `shutdownNow` возвращает список не начавшихся задач — посчитайте их.

**Дополнительно:** замените `Thread.sleep(200)` в задаче на `Thread.sleep(5000)`. Убедитесь, что `shutdownNow` действительно прерывает задачи, и все они логируют «прервана».

## Задача 7. Диагноз по симптому

**Что комбинируется:** всё.

Вам даны три программы. Каждая **не работает** — но по-разному. Определите проблему и предложите исправление.

**Программа А:**

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
for (int i = 0; i < 1_000_000; i++) {
    pool.execute(() -> { /* мелкая работа */ });
}
// main завершается, pool.shutdown() не вызван
```

**Программа Б:**

```java
ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(2);
scheduler.scheduleAtFixedRate(() -> {
    System.out.println("Тик");
    if (Math.random() < 0.01) throw new RuntimeException("Сбой");
}, 0, 100, TimeUnit.MILLISECONDS);
Thread.sleep(60_000);
```

**Программа В:**

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
for (int i = 0; i < 100; i++) {
    pool.submit(() -> { throw new RuntimeException("всегда падает"); });
}
pool.shutdown();
pool.awaitTermination(10, TimeUnit.SECONDS);
System.out.println("Пул завершён, всё ок"); // ← а задачи-то падали
```

**Вопросы:**

1. Что произойдёт с программой А через несколько минут? Почему?
2. Через сколько времени программа Б перестанет печатать «Тик»? Почему?
3. Почему программа В печатает «всё ок», хотя все 100 задач упали?

## Задача 8. Резюме в одном приложении

**Что комбинируется:** всё.

Напишите **параллельный загрузчик-обработчик** данных с тремя пулами.

**Сценарий:**

1. **Пул `downloaders`** (`newFixedThreadPool(8)`) — «скачивает» 100 файлов (по 100 мс каждый).
2. **Пул `processors`** (`ThreadPoolExecutor(4, 8, 30s, ArrayBlockingQueue(20))` с `CallerRunsPolicy`) — «обрабатывает» каждый файл (по 200 мс).
3. **Пул `scheduler`** (`newScheduledThreadPool(1)`) — раз в 500 мс печатает статистику: скачано, обработано, в очереди.

**Требования:**

1. Задачи в `downloaders` после завершения отправляют результат в `processors`.
2. `scheduler` — демон, завершается по `interrupt`.
3. После того как все файлы обработаны — корректно завершить все три пула.
4. Сводка: сколько скачано, сколько обработано, сколько упало (если что-то падало — ловите `Future.get()`).

**Что проверяется:** умение собрать несколько пулов в конвейер, не перепутать типы, корректно завершить всё.

## 🎯 Проектное задание. Мини-фреймворк параллельной обработки

Это задание сложнее предыдущих. Оно не про конкретный пул, а про **дизайн**.

### Постановка

Напишите класс `ParallelProcessor<T, R>`, который принимает список элементов и функцию обработки, и возвращает список результатов.

1. Принимает: `List<T> input`, `Function<T, R> processor`, `int concurrency`.
2. Внутри — свой `ThreadPoolExecutor` с `concurrency`, ограниченной очередью, `CallerRunsPolicy`.
3. Обрабатывает все элементы параллельно, результаты складывает в общий массив **по индексу** (без синхронизации).
4. Если обработка элемента упала — записывает `null` в результат и увеличивает счётчик ошибок.
5. Возвращает объект `Result<R>` с полями:
   - `List<R> results` — результаты (где ошибка — `null`);
   - `List<Integer> failedIndexes` — индексы упавших элементов;
   - `long elapsedMillis` — время выполнения;
   - `int concurrency` — сколько потоков было использовано.
6. Корректно завершает пул в `finally`.

### Дополнительно

7. Добавьте метод `parallelForEach`, который принимает `Consumer<T>` и не возвращает результатов.
8. Добавьте возможность **прервать** обработку через `cancel()`. После `cancel` новые задачи не отправляются, а уже выполняющиеся прерываются.
9. Добавьте `addShutdownHook`, который при завершении JVM логирует статистику и завершает пул.

### Тесты

1. 1000 чисел, `x -> x * 2`, `concurrency = 4`. Результат — массив удвоенных чисел.
2. 1000 чисел, `x -> { if (x % 10 == 0) throw ...; return x; }`. Проверьте: 100 элементов `null` в `results`, 100 индексов в `failedIndexes`.
3. `cancel()` через 100 мс после старта. Оставшиеся задачи не выполняются, статистика корректна.

3. Как бы вы реализовали **приоритеты** в этой задаче — обрабатывать сначала важные элементы?
