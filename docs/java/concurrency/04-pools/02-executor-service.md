# 4.2. ExecutorService и Executors

## Где вы это уже видели

**Диспетчер такси.** Вы не звоните водителю напрямую и не объясняете ему, как устроен город. Вы звоните **диспетчеру**: «Нужна машина на Ленина, 5». Диспетчер сам решает, какую машину послать, сколько ждать, что делать, если свободных нет. Вам важен результат — доехать. А как именно это устроено внутри — не ваша забота.

**Отдел кадров.** Вы не нанимаете сотрудника сами — вы подаёте заявку в отдел кадров: «Нужен разработчик на проект». Отдел кадров решает, кого взять, откуда, на какой срок. Вы получаете сотрудника и работаете с ним. Все формальности — на их стороне.

**Служба доставки.** Вы оформляете заказ — и всё. Дальше служба сама решает: какого курьера назначить, какой маршрут выбрать, что делать, если курьер заболел. Вы только получаете уведомление «заказ доставлен» или «заказ задерживается».

**Общее во всех случаях** одно: есть **исполнитель**, который берёт на себя всю «механику», и вы взаимодействуете с ним через **простой интерфейс**. Вам не нужно знать, сколько у него машин, как он их выбирает, что делает в случае сбоя. Вы просто говорите «сделай» — и получаете результат.

В Java этот «диспетчер» называется **`ExecutorService`**. А **`Executors`** — это отдел кадров, который этих диспетчеров создаёт.

## Теория

### ExecutorService: интерфейс, а не класс

`ExecutorService` — это **интерфейс** из `java.util.concurrent`. Он описывает, **что** умеет пул, но не **как** он это делает. Это важно: за интерфейсом могут стоять разные реализации — фиксированный пул, кеширующий, однопоточный, отложенный. Но работать с ними вы будете одинаково.

Основные методы, которые вам понадобятся.

**`void execute(Runnable task)`** — «выполни эту задачу». Не возвращает результата, не даёт способа дождаться. Просто «выполни когда-нибудь».

**`Future<?> submit(Runnable task)`** — «выполни эту задачу и дай мне `Future`». Через `Future` можно узнать, закончилась ли задача, и дождаться её завершения.

**`<T> Future<T> submit(Callable<T> task)`** — то же, но задача возвращает результат. `Callable<T>` — это как `Runnable`, но с возвращаемым значением и возможностью бросить проверяемое исключение. О нём — в главе 6.1.

**`void shutdown()`** — «заверши работу, когда закончишь текущие задачи». Новые задачи приниматься не будут, но уже начатые доработают.

**`List<Runnable> shutdownNow()`** — «заверши работу немедленно». Прерывает выполняющиеся задачи, возвращает список задач, которые не успели начаться.

**`boolean awaitTermination(long timeout, TimeUnit unit)`** — «подожди, пока пул не завершится». Возвращает `true`, если дождались, `false` — если таймаут.

**`boolean isShutdown()`** — «пул уже начал завершаться?».

**`boolean isTerminated()`** — «пул полностью завершился?».

<div style="background-color: #1E0F33; border-left: 4px solid #B388FF; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #B388FF;">Правило:</strong> программируйте под <code>ExecutorService</code>, а не под конкретную реализацию. Тогда завтра вы сможете заменить фиксированный пул на виртуальные потоки или на другой пул — и код не придётся переписывать.
</div>

### Executors: фабрика пулов

`Executors` — это **утилитный класс** со статическими методами. Он создаёт готовые реализации `ExecutorService` под типичные сценарии. Не нужно самому собирать пул из кусочков — просто вызовите подходящий метод.

Вот главные фабричные методы.

### newFixedThreadPool: фиксированный пул

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
```

Создаёт пул с **фиксированным** числом потоков. Сколько задач ни пришло бы — работают не больше четырёх одновременно. Остальные ждут в очереди.

**Когда использовать:** когда у вас CPU-bound задачи и вы знаете, сколько ядер на машине. Классика: `newFixedThreadPool(Runtime.getRuntime().availableProcessors())` — по одному потоку на ядро.

**Особенности:**

- Потоки создаются **по мере необходимости**, но не больше `N`. Если пришла одна задача — создастся один поток. Пришла вторая — второй. И так до `N`.
- Если поток упал с исключением — на его место создаётся новый. Пул не «худеет».
- Очередь задач **неограниченная** (`LinkedBlockingQueue` без размера). Это значит: если задачи приходят быстрее, чем выполняются, они копятся в памяти. Может закончиться `OutOfMemoryError`.

### newCachedThreadPool: кеширующий пул

```java
ExecutorService pool = Executors.newCachedThreadPool();
```

Создаёт пул, который **создаёт новый поток под каждую задачу**, если нет свободного. Потоки, которые простаивают **больше 60 секунд**, уничтожаются.

**Когда использовать:** для коротких задач, которых много и которые быстро выполняются. Например, обработка мелких событий, где важна скорость реакции, а не экономия памяти.

**Особенности:**

- Верхней границы числа потоков **нет**. Если пришла тысяча задач одновременно — будет создана тысяча потоков (если ни один не освободился). Это может убить программу.
- Потоки переиспользуются, если есть свободные. Если задача пришла, а свободных нет — создаётся новый.
- Очередь — `SynchronousQueue` (по сути, «нет очереди»). Задача либо сразу передаётся свободному потоку, либо под неё создаётся новый.

**Осторожно:** `newCachedThreadPool` — **коварный** пул. Он выглядит удобным: «сам разберётся, сколько потоков нужно». Но под нагрузкой он может создать столько потоков, что программа упадёт. Используйте, только если точно понимаете, что делаете.

### newSingleThreadExecutor: один поток

```java
ExecutorService pool = Executors.newSingleThreadExecutor();
```

Создаёт пул из **одного** потока. Все задачи выполняются **последовательно**, в порядке прихода.

**Когда использовать:** когда задачи должны выполняться строго по одной, в порядке поступления. Например, обработка событий, где важен порядок; или доступ к ресурсу, который не потокобезопасен.

**Особенности:**

- Все задачи — в одной очереди, выполняются одним потоком.
- Если поток упадёт — создаётся новый, и работа продолжается.
- Это, по сути, асинхронная замена «одного выделенного потока для всего».

### newScheduledThreadPool: отложенные задачи

```java
ScheduledExecutorService pool = Executors.newScheduledThreadPool(2);
```

Создаёт пул, который умеет выполнять задачи **с задержкой** или **периодически**. Возвращает `ScheduledExecutorService` — наследника `ExecutorService` с дополнительными методами. Подробно — в главе 4.4.

**Когда использовать:** для таймеров, периодических задач, отложенных действий.

### newWorkStealingPool: с кражей работы

```java
ExecutorService pool = Executors.newWorkStealingPool();
```

Создаёт пул на основе `ForkJoinPool` с числом потоков, равным числу ядер. Использует «кражу работы»: если один поток простаивает, он «крадёт» задачи у других. Подробно — в главе 4.6.

**Когда использовать:** для задач, которые можно рекурсивно разбить на подзадачи. Не для обычных мелких задач.

### Сводная таблица

| Фабрика | Размер | Очередь | Когда использовать |
|---|---|---|---|
| `newFixedThreadPool(n)` | Фиксированный `n` | Неограниченная | CPU-bound задачи |
| `newCachedThreadPool()` | Неограничен | `SynchronousQueue` | Много коротких задач |
| `newSingleThreadExecutor()` | 1 | Неограниченная | Последовательная обработка |
| `newScheduledThreadPool(n)` | Фиксированный `n` | Задержанная очередь | Таймеры, периодика |
| `newWorkStealingPool()` | = числу ядер | Work-stealing | Рекурсивные задачи |

### Как выполнять задачи

Самый простой способ — `execute`:

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
for (int i = 0; i < 10; i++) {
    int id = i;
    pool.execute(() -> {
        System.out.println("Задача " + id + " выполняется в " + Thread.currentThread().getName());
    });
}
```

**Возможный вывод** (порядок случайный, часть задач может выполниться в одном потоке):

```text
Задача 0 выполняется в pool-1-thread-1
Задача 1 выполняется в pool-1-thread-2
Задача 2 выполняется в pool-1-thread-3
Задача 3 выполняется в pool-1-thread-4
Задача 4 выполняется в pool-1-thread-1
Задача 5 выполняется в pool-1-thread-2
...
```

Обратите внимание на имена потоков: `pool-1-thread-1`, `pool-1-thread-2` и так далее. Это имена, которые `Executors` даёт потокам автоматически. Как мы говорили в главе 1.7, имена важно давать осмысленные — но для быстрых экспериментов и такие сойдут.

### submit и Future

`execute` удобен, когда результат не нужен. Если нужен — `submit`:

```java
ExecutorService pool = Executors.newFixedThreadPool(4);

Future<Integer> future = pool.submit(() -> {
    Thread.sleep(1000);
    return 42;
});

// ... можно делать что-то ещё

Integer result = future.get(); // блокируется, пока не будет результат
System.out.println("Результат: " + result);
```

`Future.get()` — блокирующий. Пока задача не завершится — поток ждёт. Если задача бросит исключение — `get()` его пробросит, обёрнутым в `ExecutionException`.

Подробно про `Future` и `Callable` — в главе 6.1. Пока достаточно знать, что `submit` даёт способ дождаться результата, а `execute` — нет.

### Завершение пула

Это важная тема, и ей посвящена отдельная глава 4.5. Пока — краткая суть.

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
// ... работа

pool.shutdown(); // вежливо: дай доработать текущим, новые не принимай
// или
pool.shutdownNow(); // грубо: прерви текущие, не начатые — верни

// дождаться завершения
if (pool.awaitTermination(10, TimeUnit.SECONDS)) {
    System.out.println("Пул завершён");
} else {
    System.out.println("Пул не завершился за 10 секунд");
}
```

**Ключевое:** `ExecutorService` **не является демоном** по умолчанию. Потоки в пуле — обычные. Если вы не вызовете `shutdown()`, программа будет висеть, даже когда все задачи выполнены. Это самая частая ошибка новичков: запустили пул, выполнили задачи, забыли `shutdown()` — программа не завершается, приходится убивать вручную.

<div style="background-color: #1E0F33; border-left: 4px solid #B388FF; padding: 1rem; margin: 1.5rem 0;">
  <strong style="color: #B388FF;">Правило:</strong> если создали <code>ExecutorService</code> — обязательно вызовите <code>shutdown()</code> или <code>shutdownNow()</code>. Иначе потоки будут держать программу вечно. Это правило без исключений.
</div>

### try-with-resources

Начиная с Java 19, `ExecutorService` реализует `AutoCloseable`. Это значит, что можно использовать try-with-resources — и пул закроется автоматически:

```java
try (ExecutorService pool = Executors.newFixedThreadPool(4)) {
    pool.execute(() -> System.out.println("Работаю"));
    pool.execute(() -> System.out.println("Тоже работаю"));
}
// здесь pool.shutdown() уже вызван автоматически
```

Это удобно и уменьшает шанс забыть `shutdown()`. Но работает только в Java 19+. Для более старых версий — обычный `try/finally`.

### Частые ошибки

**Ошибка 1: забыть `shutdown()`.** Программа не завершается. Потоки пула — обычные, не демоны, держат JVM. Всегда `shutdown()` в `finally` или try-with-resources.

**Ошибка 2: `newCachedThreadPool` под нагрузкой.** Пул создаёт поток под каждую задачу, если нет свободных. Под пиковой нагрузкой это может быть тысяча потоков, и программа упадёт от `OutOfMemoryError` или откажется работать из-за переключений контекста.

**Ошибка 3: задачи теряются при `shutdownNow`.** `shutdownNow()` прерывает выполняющиеся задачи и **возвращает** список тех, что не успели начаться. Если вы этот список игнорируете — задачи потеряны. Если это неприемлемо — используйте `shutdown()` и дожидайтесь.

**Ошибка 4: неправильный размер пула.** Слишком маленький — задачи копятся, программа тормозит. Слишком большой — конкуренция, переключения, падение производительности. Для CPU-bound — примерно число ядер. Для I/O-bound — больше.

**Ошибка 5: смешивать разные типы задач в одном пуле.** Если в одном пуле и CPU-bound, и I/O-bound задачи — I/O-bound задачи будут занимать потоки, пока ждут. CPU-bound задачи в это время стоят в очереди. Лучше — **два отдельных пула** для разных типов.

**Ошибка 6: игнорировать `Future`.** Если задача вернула `Future`, а вы его не проверяете — вы не узнаете, упала ли она. Исключения в задачах не пробрасываются в вызывающий поток автоматически, они хранятся в `Future`. Если `Future` не проверять — исключения теряются. Это подробно разбирается в модуле 6.

### Аналогия с диспетчером

Вернёмся к началу. `ExecutorService` — это **диспетчер такси**. Вы звоните, говорите «нужна машина» — и он разбирается. Сколько у него машин, как он их выбирает, что делает, если свободных нет, — не ваша забота. Вы получаете машину (или уведомление «ждите»).

`Executors` — это **служба, которая нанимает диспетчеров**. Есть диспетчер «на четыре машины» (`newFixedThreadPool`), «на любое количество» (`newCachedThreadPool`), «один водитель на всё» (`newSingleThreadExecutor`). Вы выбираете, какой диспетчер вам подходит, — и работаете с ним.

`shutdown()` — это «закончил работу, распусти диспетчеров». Если не позвать — они будут сидеть и ждать звонков, даже когда клиентов уже нет.

## Микрозадача 1: сравнить newFixedThreadPool и newCachedThreadPool

**Задача:** Создайте два пула — `newFixedThreadPool(2)` и `newCachedThreadPool()`. Отправьте в каждый по 10 задач, каждая печатает имя потока и спит 500 мс. Сравните имена потоков в выводе.

**Решение:**

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> {
            System.out.println("Поток: " + Thread.currentThread().getName());
            try { Thread.sleep(500); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        };

        System.out.println("=== Fixed(2) ===");
        ExecutorService fixed = Executors.newFixedThreadPool(2);
        for (int i = 0; i < 10; i++) fixed.execute(task);
        fixed.shutdown();
        fixed.awaitTermination(10, TimeUnit.SECONDS);

        System.out.println("=== Cached ===");
        ExecutorService cached = Executors.newCachedThreadPool();
        for (int i = 0; i < 10; i++) cached.execute(task);
        cached.shutdown();
        cached.awaitTermination(10, TimeUnit.SECONDS);
    }
}
```

**Возможный вывод:**

```text
=== Fixed(2) ===
Поток: pool-1-thread-1
Поток: pool-1-thread-2
Поток: pool-1-thread-1
Поток: pool-1-thread-2
Поток: pool-1-thread-1
Поток: pool-1-thread-2
...
=== Cached ===
Поток: pool-2-thread-1
Поток: pool-2-thread-2
Поток: pool-2-thread-3
Поток: pool-2-thread-4
Поток: pool-2-thread-5
Поток: pool-2-thread-6
...
```

**Разбор:** `newFixedThreadPool(2)` переиспользует **два** потока: `thread-1` и `thread-2`. Остальные задачи ждут в очереди, пока один из двух не освободится. `newCachedThreadPool` создаёт **новый поток под каждую задачу**, потому что все предыдущие заняты (спят). К концу — десять разных потоков. Оба варианта завершились, но по-разному: первый — последовательно по 2, второй — параллельно по 10.

## Микрозадача 2: показать забытый shutdown

**Задача:** Напишите программу, которая создаёт `newFixedThreadPool(2)`, отправляет одну задачу, дожидается её через `Future.get()` — и **не вызывает** `shutdown()`. Убедитесь, что программа **не завершается** после выполнения задачи.

**Решение:**

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(2);
        System.out.println("Отправляю задачу");
        pool.submit(() -> System.out.println("Задача выполнена")).get();
        System.out.println("Задача завершена, но main не завершается");

        // забыли pool.shutdown()
    }
}
```

**Возможный вывод:**

```text
Отправляю задачу
Задача выполнена
Задача завершена, но main не завершается
```

И дальше — тишина. Программа висит. Приходится нажимать Ctrl+C.

**Разбор:** `main` завершил работу, но JVM не может выйти, потому что в пуле остались **два не-демон потока** — `pool-1-thread-1` и `pool-1-thread-2`. Они ждут новых задач в очереди. JVM не завершится, пока все обычные потоки не закончатся. А они не закончатся, пока не вызовут `shutdown()`.

**Исправление:** добавить `pool.shutdown()` в конце (или в `finally`). После этого потоки пула завершатся, и JVM спокойно выйдет.

## 🎯 Самостоятельная задача

Напишите **параллельный загрузчик файлов** на `ExecutorService`.

**Постановка:**

1. Есть список из 20 «URL-адресов» (строки вида `"http://example.com/file-N"`).
2. Каждый «файл» загружается 300–800 мс (случайное время).
3. Нужно «загрузить» все файлы параллельно, но **не более 4 одновременно**.
4. Результаты (имя файла, время загрузки, размер) складывать в общий список.

**Требования:**

1. Используйте `Executors.newFixedThreadPool(4)`.
2. Каждая загрузка — это `Callable<FileResult>`, возвращающий результат.
3. Соберите все `Future<FileResult>` в список, потом пройдитесь по нему и дождитесь результатов через `get()`.
4. Сложите результаты в общий список **из главного потока** — тогда не нужна синхронизация.
5. В конце — `shutdown()` и `awaitTermination`.
6. Выведите сводку: сколько файлов загружено, общий размер, общее время.
